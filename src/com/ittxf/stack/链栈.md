## 一、一句话：把栈顶对准链表头部

栈的要求是"进出都在同一端"，链表恰好最擅长的就是"在头部挂一个、摘一个"，两者一拍即合：

```
   top ──► ┌─────┐     ┌─────┐     ┌─────┐
           │  3  ├────►│  2  ├────►│  1  ├────► null
           └─────┘     └─────┘     └─────┘
            栈顶        （往里）      栈底

   入栈 4：在头部挂一个新节点，top 挪一格
   top ──► [4] ──► [3] ──► [2] ──► [1] ──► null
   出栈：把头部这个摘掉，top 再挪回一格
```

**为什么不对准链表尾部？** 因为尾部插入虽然方便（有 `tail` 指针时 O(1)），**但"摘除尾部节点"拿不到它的前驱**（单链表是单向的），得从头走到尾，出栈就退化成 O(n)。栈的两个核心操作必须都快，所以只能对准头部。

| 栈顶开在哪一端 | push | pop | 结论 |
|---|---|---|---|
| **链表头部**（本代码） | O(1) | O(1) | ✅ 唯一合理选择 |
| 链表尾部（带 `tail`） | O(1) | **O(n)**（找不到前驱） | ❌ 出栈太慢 |
| 链表尾部（不带 `tail`） | O(n) | O(n) | ❌ 更糟 |

## 二、`top` 的含义彻底变了（最容易懵的一点）

数组版和链栈版的"栈顶指针"是**两种完全不同的东西**，名字一样，类型不同：

| | 数组版 `ArrayStack` | 链栈版 `LinkedStack` |
|---|---|---|
| `top` 的类型 | `int`（数组**下标**） | `StackNode`（**节点引用**） |
| 指向 | 栈顶元素所在的那一格 | 栈顶元素**那个节点本身** |
| 空栈的表示 | `top == -1` | `top == null` |
| 判满 | `top == maxSize - 1` | ❌ **不存在这个概念** |
| 入栈 | `top++; arr[top] = value;` | `node.next = top; top = node;` |
| 出栈 | `value = arr[top]; top--;` | `top = top.next;`（旧节点自然脱链） |
| 栈里有几个 | `top + 1`（O(1)，下标天然是计数） | 下标没了，得数节点（O(n)）或额外存 `count` |

一句话记住这个转变：**数组版靠"格子编号"定位，链栈靠"节点引用"定位；从 `top--` 到 `top = top.next`，是把整数的加减换成了指针的跳转。**

```java
private StackNode top;   // 默认为 null，正好就是"空栈"，构造里不需要写任何初始化
private int count;       // 元素个数，见第五节
```

## 三、`push`：两句的顺序是铁律

```java
StackNode node = new StackNode(data);
node.next = top;   // ① 新节点先接住原来整条链
top = node;        // ② 再把 top 交给新节点
count++;
```

```
   入栈前：top ──► [3] ──► [2] ──► [1] ──► null        node(4).next = null

   ① node.next = top          ② top = node
   node ──► [3] ──► [2] ──► [1]     top ──► node ──► [3] ──► [2] ──► [1]
   （旧链先被新节点攥住）              （top 才敢挪走）
```

**反例（顺序写反）**：

```java
top = node;        // 先挪 top
node.next = top;   // 此时 top 就是 node 自己 → node.next = node
```

后果有两层：**旧链 `[3]→[2]→[1]` 当场失联**（没有任何指针指着它们，全被 GC 收走），而且新节点指向自己，`list()` 一遍历就是**死循环**。这跟单链表 [addByOrder 的"先接后断"](../linkedlist/%E5%8D%95%E9%93%BE%E8%A1%A8.md)、反转的"① 存后路"（逐帧动画见 [单链表反转动画.html](../linkedlist/%E5%8D%95%E9%93%BE%E8%A1%A8%E5%8F%8D%E8%BD%AC%E5%8A%A8%E7%94%BB.html)）是同一条铁律：

> **改一个指针之前，必须先确认这个指针原来连着的东西还有别人能找到它。**

## 四、`pop`：先取值、再挪指针、最后断干净

```java
if (isEmpty()) throw new RuntimeException("栈空，无法出栈");
StackNode oldTop = top;
int value = oldTop.data;      // ① 先把值存住
top = top.next;               // ② top 后移一格（新栈顶可能是 null）
oldTop.next = null;           // ③ 把弹出节点的线剪断
count--;
return value;                 // ④ 返回旧值
```

顺序也不能乱：如果先 `top = top.next` 再 `return top.data`，返回的就是**第二个**元素了（跟队列 `getQueue` 一模一样的错法）。

**第 ③ 句是链栈特有的**，数组版不需要：数组版出栈只是 `top--`，格子里的旧数据留着无害（下次入栈会被覆盖，或者被越过）。而链栈把节点摘下来之后，如果它还被别处引用着（比如你外面存了个 `StackNode ref = stack.peekNode()`），那条 `next` 就会让**后面一整串已经出栈的节点都回收不掉**。JDK 的 `ArrayDeque.poll` 也是同样处理：

```java
elements[tail] = null;   // JDK 源码里显式清空，防止"忘不掉的引用"
```

## 五、`count` 这个字段：一个典型的工程取舍

数组版 `size()` 是免费的（`top + 1`），链栈没有下标，只有两条路：

```java
// 方案 A：不存 count，每次遍历数一遍
public int size() {
    int n = 0;
    for (StackNode p = top; p != null; p = p.next) n++;
    return n;                      // O(n)
}

// 方案 B（本代码）：多存一个 int count，push/pop 各同步一句
private int count;
public int size() { return count; } // O(1)
```

| | 方案 A 遍历 | 方案 B 冗余字段 |
|---|---|---|
| `size()` 成本 | O(n) | **O(1)** |
| 内存 | 一个 int 都不用 | 多一个 int |
| 风险 | 无 | push 加了、pop 忘了减 → **幽灵不一致**，而且编译器不会提醒 |

这跟 [环形队列.md](../queue/%E7%8E%AF%E5%BD%A2%E9%98%9F%E5%88%97.md) 第九节讲的"牺牲一格 vs 加一个 size 字段"是同一类决策：**用"多维护一个字段"换"计算变简单"**。代价永远是同步维护，所以 `push`/`pop` 里那两句 `count++`/`count--` 一定要成对出现（我是实测过的：连续 push 3 个、pop 3 个之后 `size` 从 3 归 0 ✅）。

## 六、链栈天生没有"假满"问题

[队列.md](../queue/%E9%98%9F%E5%88%97.md) 第五节那个坑值得回收一次：数组队列出队后 `front` 前的格子复用不了，因为**入口和出口在数组的两端**，指针只往后走，中间的空白永远够不着。

```
   数组队列（两端分开）：              数组栈 / 链栈（同一端）：
   [作废][作废][ 3 ][ 4 ]  ← 报满        top 只在一端进退，pop 之后 push 立刻复用同一格
    ↑front          ↑rear                所以数组版栈不会有"假满"
```

也就是说：**"假满"是队列独有的问题，栈（无论数组还是链表）都没有它**。那链栈相对数组栈还剩什么优势？只剩一条：**没有 `maxSize`，不需要预先估容量，也不会因为估小了要扩容重排**。数组栈要扩张得新建数组、逐个搬；链栈直接 `new` 一个节点就完了。

反过来链栈付出的代价：

- 每个元素多背一个引用（64 位 JVM 约 4~8 字节），而数组只存数据本身
- 节点在堆上是散落的，遍历时的**缓存局部性**远不如连续数组
- 每次 push 都要 `new` 对象，频繁入栈出栈时 GC 压力更大

```
   选择口诀：容量能估准、要极致性能 → 数组栈；
             容量估不准、或干脆不知道有多深（比如递归/表达式栈）→ 链栈
```

## 七、全维度对照总表

| 维度 | 数组栈 `ArrayStack` | 链栈 `LinkedStack` |
|---|---|---|
| 存数据的东西 | `int[] arr`（连续） | 散落的 `StackNode` 对象 |
| 栈顶指针语义 | 下标 `int top`（-1 = 空） | 引用 `StackNode top`（null = 空） |
| 需要预设容量 | ✅ `maxSize` | ❌ 不需要 |
| 判满 | `top == maxSize - 1`，满了 push 只打印提示 | 不存在（除非堆内存耗尽 OOM） |
| `push` | O(1)（判满 + 两句话） | O(1)（new 节点 + 两句话） |
| `pop` / `peek` | O(1) | O(1) |
| `size` | O(1)（`top + 1`） | O(1)（靠 `count`）／不存就 O(n) |
| 越界风险 | 有（下标算错就 `ArrayIndexOutOfBounds`） | 几乎没有，但**有 null 解引用风险**（`top.next` 之类） |
| 内存 | 省（只有数组本体） | 费（每节点多一根 next + 对象头） |
| 典型代表 | 自己的 `ArrayStack` | `StackNode` 版；JDK 里 `LinkedList` 当栈用 |

## 八、异常策略：和前面几个程序保持同一条规矩

```java
public void push(int data)   // void：链栈不会满，直接干活，不需要失败处理
public int pop()             // 有返回值：空栈时返回哪个数都可能是真实数据 → throw RuntimeException
public int peek()            // 同上 → throw
public void list()           // void：空栈打印"栈空，无法遍历"就够
```

`main` 里 `case "pop"`/`case "peek"` 用 `try-catch` 接住，程序不会崩，继续回菜单 —— 这套判断标准来自 [队列.md 第六节](../queue/%E9%98%9F%E5%88%97.md)：**方法有没有返回值，决定它失败时该"打印"还是该"抛异常"**。

顺带一个改进点：链栈这里 `switch` 写了 `default` 并给出提示，而 `ArrayStackDemo` 的菜单里印了 `list: 显示栈` 却没有 `case "list"`，输入 `list` 会落到空的 default 静默无反应（实测见下一节）。

想再挖两层的实验：

| 实验 | 怎么改 | 会看到什么 | 印证哪一节 |
|---|---|---|---|
| 1 | 把 `push` 里两句顺序对调（先 `top = node;` 再 `node.next = top;`） | 后续 `show` **卡死不返回**（自环死循环），且原有数据全丢 | 第三节反例 |
| 2 | 删掉 `count` 字段，`size()` 改成遍历计数 | 输出不变，但能体感"每次问个数都要跑一遍链" | 第五节取舍 |
| 3 | `pop` 里漏掉 `count--` | 弹完 3 个后 `size` 仍报 3 —— 冗余字段不同步的典型症状 | 第五节风险 |
| 4 | 把 `pop` 改成先 `top = top.next` 再 `return top.data` | 弹出顺序变成 2、（然后栈空异常），把队首跳过了 | 第四节顺序 |
| 5 | 连 push 一万个数（数组版设 `maxSize = 4`） | 链栈一路正常；数组版第 5 个开始报"栈满，无法入栈" | 第六节差别 |

## 十、一句话记住链栈

> **链栈 = 单链表的节点 + 栈的规矩：栈顶必须开在链表头部（只有这一端 push/pop 都是 O(1)，尾部删除找不到前驱）；`top` 从"下标"变成"节点引用"，空栈从 `-1` 变成 `null`，于是再没有 `maxSize`、没有判满、也没有队列那种假满；入栈必须"先让新节点接住旧链、再挪 top"（写反就整链失联 + 自环死循环）；出栈是"存值 → top 后移 → 把摘掉节点的 next 置 null"，最后那个置 null 是链栈比数组版多出来的一道收尾。**

## 十一、往下学什么

1. **把 `count` 去掉**，改成遍历数一遍，亲手比较两种 `size()` 的代价（第五节那张表的体感版）。
2. **用这个链栈写逆波兰计算器**：后缀表达式求值只要一个栈（数字压栈、遇到运算符弹出两个再压回），是栈最经典的实战，也是本目录唯一还没写的实战。
3. **双向链栈 / 带 `tail` 的链栈**：想想为什么这里两个都不需要（栈只用一端，多一根线纯属浪费）—— 判断"要不要加字段"的能力比会写代码更值钱。
4. **对照 JDK**：`ArrayDeque`（循环数组，和数组栈一家）与 `LinkedList`（双向链表，可当链栈）的 `push/pop/peek` 就是本篇接口的工业版，看看它们的 `first`/`last` 命名怎么对应你的 `top`。
5. **数组版也已成篇**：[数组栈.md](./%E6%95%B0%E7%BB%84%E6%A0%88.md) 讲的是同一件事的另一种地基 —— 重点看 `top` 从“节点引用”变回“数组下标”之后，`push`/`pop` 的前后置自增为什么会反过来，以及它和链栈在容量、`size()`、缓存局部性上的得失。

> 对应程序：[PolandNotation.java](./PolandNotation.java)（课程版）、[ReversePolishCalculator.java](./ReversePolishCalculator.java)（同一套写法，补上小数、空白过滤、括号校验）

> 栈的原理见 [数组栈.md](./%E6%95%B0%E7%BB%84%E6%A0%88.md)、[栈.md](../linkedlist/%E6%A0%88.md)。

## 一、三种写法，为什么后缀最好算

同一个式子 `3 + 4 × 5 − 6`，三种写法：

| 名字 | 写法 | 运算符位置 |
|---|---|---|
| 中缀（人习惯的） | `3 + 4 * 5 - 6` | 两个操作数**中间** |
| 前缀（波兰式） | `- + 3 * 4 5 6` | 操作数**前面** |
| 后缀（逆波兰式） | `3 4 5 * + 6 -` | 操作数**后面** |

中缀难算，是因为计算机必须知道"**什么时候该算、什么时候该等**"：`*` 要比 `+` 先算，括号要最先算 —— 这就是 [双栈计算器.md](./%E5%8F%8C%E6%A0%88%E8%AE%A1%E7%AE%97%E5%99%A8.md) 里那一整套优先级比较和括号逻辑的由来。

后缀式把这件事**提前解决了**：它的书写顺序就是运算顺序，从左往右扫，遇到运算符就必然"两个操作数已经齐了"。所以：

> **后缀求值不需要知道优先级，也不需要认识括号 —— 因为它压根不会出现运算符需要"等一等"的情况。**

```
   3 4 5 * + 6 -
   ↑   ↑ ↑ ↑   扫到 * ：栈里有 3,4,5 → 拿 4 和 5 算 → 20 入栈
       └─┴─┘   扫到 + ：栈里有 3,20  → 拿 3 和 20 算 → 23 入栈
                 ↑ 扫到 - ：栈里有 23,6 → 拿 23 和 6 算 → 17 = 结果
   全程没有任何"要不要再等等"的判断
```

## 二、三步流水线

```
   "1+((2+3)*4)-5"
        │  ① 分词 infixToList / infixToSuffix(String)
        ▼
   [1, +, (, (, 2, +, 3, ), *, 4, ), -, 5]
        │  ② 调度场算法 parseSuffixExpres / infixToSuffix(List)   ← 用符号栈 s1
        ▼
   [1, 2, 3, +, 4, *, +, 5, -]
        │  ③ 求值 calculate                                       ← 用一个数栈
        ▼
   16
```

为什么要先切成 List，而不是直接对字符串操作？因为**多位数**：字符串里 `"12"` 是两个字符，作为数字是一个整体。先切成 token 列表，后面两步就只看"这个 token 是数还是符"，不用再操心字符边界。

## 三、① 分词：一次吃掉一个完整的数

```java
// ReversePolishCalculator.infixToList
if (isBlank(c)) { i++; }                          // 空白直接跳过
else if (isNumChar(c)) {                          // 数字或小数点 → 往后拼到底
    str = "";
    while (i < len && isNumChar(expression.charAt(i))) { str += expression.charAt(i); i++; }
    if (!str.matches("\\d+(\\.\\d+)?")) throw new RuntimeException("不是一个合法数字：" + str);
    list.add(str);
}
else if (c == '+' || ... || c == ')') { list.add(String.valueOf(c)); i++; }   // 单字符 token
else throw new RuntimeException("表达式含非法字符：" + c);
```

两个要点：

1. **拼完要验一下**：`1.2.3` 会被"数字+小数点"的规则一路拼成 `"1.2.3"`，不校验的话它会一路混到求值阶段才炸。提前报"不是一个合法数字"。
2. **判断"下一位是不是数字"，别判断"下一位是不是非运算符"**。`PolandNotation` 的分词用的是 `c < 48 || c > 57`（非数字即运算符），于是小数点 `.` 会被当成独立 token、`)` 也可能被拼进数字里 —— 这是它不支持小数的根因。

## 四、② 中缀 → 后缀（调度场算法）

规则只有四条，全部围绕"符号栈 `s1`"：

| 遇到的 token | 动作 |
|---|---|
| 数字 | 直接进结果列表 `s2` |
| `(` | 直接压进 `s1` |
| `)` | 把 `s1` 的运算符逐个弹出进结果，**直到遇到 `(`**；然后把 `(` 弹出丢弃（不进结果） |
| 运算符 | 只要 `s1` 栈顶的优先级 **≥** 自己的，就一直弹出进结果；停下来了再把自己压进去 |

走完再补一条：**扫描结束后，`s1` 里剩下的运算符全部弹出进结果**。

拿 `1+((2+3)*4)-5` 走一遍（实测输出就是最后那行）：

```
token   动作                                  s1（底→顶）      结果
1       数字，进结果                           []               1
+       s1 空，压入                            [+]              1
(       左括号，压入                           [+, (]           1
(       左括号，压入                           [+, (, (]        1
2       数字                                   [+, (, (]        1 2
+       栈顶是 ( → 不弹，压入                   [+, (, (, +]     1 2
3       数字                                   [+, (, (, +]     1 2 3
)       弹到 ( 为止：弹出 + ；再把 ( 丢掉        [+, (]           1 2 3 +
*       栈顶是 ( → 不弹，压入                   [+, (, *]        1 2 3 +
4       数字                                   [+, (, *]        1 2 3 + 4
)       弹到 ( 为止：弹出 * ；再把 ( 丢掉        [+]              1 2 3 + 4 *
-       栈顶 + 优先级 ≥ - → 弹出 + ；再压入 -     [-]              1 2 3 + 4 * +
5       数字                                   [-]              1 2 3 + 4 * + 5
结束     s1 剩下的全弹出                        []               1 2 3 + 4 * + 5 -
```

实测输出（`ReversePolishCalculator`）：

```
中缀表达式分割结果：[1, +, (, (, 2, +, 3, ), *, 4, ), -, 5]
中缀表达式转后缀结果：[1, 2, 3, +, 4, *, +, 5, -]
中缀表达式计算结果：16
```

**`(` 为什么能挡住结算**：`priority` 的 `else` 分支给它返回最低值，所以"栈顶是 `(`"时那个 `≥` 条件必然为假，栈里的运算符被原地封存。整个括号机制其实就是这一个数字在起作用。

`s2` 用栈还是用 List 都行，只要**最后从栈底往栈顶读**就是后缀顺序（`new ArrayList<>(s2)` 的迭代顺序正是"底→顶"，所以能直接用）。

## 五、③ 后缀求值：一个栈从头扫到尾

```java
Stack<Double> stack = new Stack<>();
for (String item : list) {
    if (是数字) stack.push(Double.parseDouble(item));
    else {
        double b = stack.pop();      // 先弹出来的是【右】操作数
        double a = stack.pop();      // 后弹出来的是【左】操作数
        stack.push(calc(a, b, item.charAt(0)));
    }
}
return stack.pop();                  // 剩下的唯一一个数就是结果
```

**顺序最容易搞错的就是 `a`、`b`**：栈是后进先出，表达式 `8 - 2` 写成后缀是 `8 2 -`，先弹出的是 `2`（右），后弹出的是 `8`（左）。所以减法和除法必须算 `a - b`（左减右），写成 `b - a` 就反了。

拿课程注释里那个例子 `3 4 + 5 * 6 -`（即 `(3+4)*5-6`）逐步看栈的变化：

```
   token   动作                        栈（底→顶）
   3       压栈                        [3]
   4       压栈                        [3, 4]
   +       弹 4、弹 3，算 3+4=7，压回    [7]
   5       压栈                        [7, 5]
   *       弹 5、弹 7，算 7*5=35，压回   [35]
   6       压栈                        [35, 6]
   -       弹 6、弹 35，算 35-6=29，压回 [29]
   结束                                 → 结果 29
```

求值结束还要检查 `stack.size() == 1`：不等于 1 说明表达式本身写坏了（比如 `3 4 5`，或者运算符太少），不检查就会把"栈顶那个数"当结果，静默出错。

## 六、两份实现的差异

`PolandNotation.java` 是课程原版，`ReversePolishCalculator.java` 是同一套写法（`java.util.Stack` + 正则判数字 + 中文注释），补了几个能落地的健壮性：

| | `PolandNotation` | `ReversePolishCalculator` |
|---|---|---|
| 数字判断 | `matches("\\d+")` | `matches("\\d+(\\.\\d+)?")` → **支持小数** |
| 求值类型 | `int` + `Integer.parseInt` | `double` + `Double.parseDouble` |
| 分词 | `c < 48 \|\| c > 57`（非数字即运算符） | `isNumChar` / `isBlank` / 运算符白名单，三分开 |
| 空白字符 | 不处理（会当成运算符） | 一律跳过（空格、`\t`、`\n`、`\r`、`\f`） |
| `)` 时 `s1` 空 | `while (!s1.peek().equals("("))` → `EmptyStackException` | 先判 `isEmpty()` → 报"多了一个右括号 )" |
| 收尾剩 `(` | 不检查，会把 `(` 当运算符传给 `switch` → 静默算成 0 | 报"少了一个右括号 )" |
| 除数为 0 | `a / b` → `ArithmeticException` | 报"除数为 0" |
| 运算符不认识 | `switch` 不匹配 → 结果 0，静默 | 抛"暂不支持的运算符：X" |
| 方法名 | 两个重载都叫 `infixToSuffix` | 拆成 `infixToList`（分词）+ `parseSuffixExpres`（转后缀） |
| 用例自测 | 无 | `main` 里 13 条用例，正常 + 异常都覆盖 |

两个都不支持的：一元负号（`-3+2`）、`%`、幂。

## 八、动手验证剧本

```powershell
javac -encoding UTF-8 -d out src\com\ittxf\stack\PolandNotation.java src\com\ittxf\stack\ReversePolishCalculator.java
java -cp out com.ittxf.stack.PolandNotation
java -cp out com.ittxf.stack.ReversePolishCalculator
```

| 实验 | 怎么改 | 会看到什么 | 印证哪一节 |
|---|---|---|---|
| 1 | 把 `calculate` 里 `a - b` 改成 `b - a` | `10-2*3` 从 4 变成 -4（`6-10`） | 第五节 a/b 顺序 |
| 2 | 把转后缀时运算符分支的 `>=` 改成 `>` | `3-2-1` 的后缀变成 `3 2 1 - -`，算出 2（应为 2？自己核对），关键是你会看到"结合性"如何影响结果 | 第四节 |
| 3 | 把 `priority` 里 `(` 的返回值从 0（else 分支）改成 9 | 括号彻底失效，`3*(2+4)` 会先算 `3*2` | 第四节末 |
| 4 | 用 `PolandNotation` 算 `3.5*2` | 崩（小数点被当独立 token，`Integer.parseInt` 接不住）；换 `ReversePolishCalculator` 得 7 | 第六节 |
| 5 | 用 `PolandNotation` 算 `3*(2+4` | 不报错，给一个错答案（`(` 被当运算符，`switch` 不匹配返回 0） | 第六节 |
| 6 | 在 `ReversePolishCalculator` 里加 `1+2*3-4/2` | 应为 5 | 全部 |

实验 3、5 最值得做：**一个把括号弄坏、一个静默给错答案**，正好是表达式解析里最典型的两类 bug。

## 九、一句话记住逆波兰计算器

> **中缀难算是因为要判断"该算还是该等"；后缀式把优先级和括号在翻译阶段就用符号栈消化掉了，所以求值时只需一个栈、从左到右扫，遇数字压栈、遇运算符弹两个数算完压回（先弹的是右操作数）；翻译本身是调度场算法：数字直接出货，`)` 弹到 `(` 为止，运算符把栈里不低于自己优先级的先弹干净再压自己，最后把栈清空 —— `(` 能挡住结算，全靠它优先级最低那一个数字。**

## 十、往下学什么

1. **[双栈计算器.md](./%E5%8F%8C%E6%A0%88%E8%AE%A1%E7%AE%97%E5%99%A8.md)**：另一条路线，对照着看"优先级和括号"在两种实现里各自藏在哪。
2. **把两遍扫描合成一遍**：边转后缀边求值（后缀式还没生成完就能算），省掉 List，这是编译器/计算器常见的单遍做法。
3. **表达式树**：中缀 → 二叉树（运算符是内部节点，数字是叶子），前中后序遍历分别对应前缀、中缀、后缀表达式 —— 一下就把三种写法串起来了。
4. **加函数与右结合运算符**：`max(1,2)`、`2^3^2`（右结合要把 `>=` 改成 `>`），是编译器前端的最小练习。
5. **`BigDecimal` 版**：`double` 算 `0.1+0.2` 会得到 `0.30000000000000004`，金融场景必须换类型（分词处把 token 直接交给 `BigDecimal` 即可，结构不动）。

## 一、结构：三个字段，一根指针

```java
private int maxSize;      // 数组的最大容量
private int[] stack;      // 真正存数据的数组
private int top = -1;     // 栈顶指针：指向"栈顶元素本身"，-1 表示栈里没人
```

```
   maxSize = 4，压入 1、2、3、4 之后的状态：

   下标      0      1      2      3
          ┌──────┬──────┬──────┬──────┐
   stack  │  1   │  2   │  3   │  4   │
          └──────┴──────┴──────┴──────┘
                                            ↑ top = 3（指着栈顶元素 4 那一格）
                                            ↑ 栈顶在最右边，进出都在这里

   空栈时：top = -1（还没进数组，在数组左边界外面）
          ┌──────┬──────┬──────┬──────┐
          │      │      │      │      │
          └──────┴──────┴──────┴──────┘
        top ↑(-1)
```

**`top` 的语义必须先钉死：它指向"栈顶元素所在的那一格"，不是"下一个空位"。** 这一个决定，推出后面所有公式。

---

## 二、四个公式，和数组队列的对照

| 问题 | 数组栈（本代码） | 数组队列（[队列.md](../queue/%E9%98%9F%E5%88%97.md)） |
|---|---|---|
| 指针数量 | **1 根**（`top`） | 2 根（`front` + `rear`） |
| 判空 | `top == -1` | `rear == front` |
| 判满 | `top == maxSize - 1` | `rear == maxSize - 1` |
| 元素个数 | `top + 1` | `rear - front` |
| 栈顶/队头是谁 | `stack[top]`（栈顶） | `arr[front + 1]`（队头，因为 front 是哨兵位） |
| 初始值 | `top = -1` | `front = -1`，`rear = -1` |

有意思的是**判满公式一模一样**：`指针顶到数组最后一格`。但两者的"满"含金量完全不同 —— 见第五节。

`top + 1` 这个个数公式解释一下：`top` 是栈顶元素的**下标**，下标从 0 数起，所以下标为 `top` 时一共有 `top + 1` 个元素。`top = -1` 时算出 0 个 ✓ 自洽。这就是为什么空栈要设 `-1` 而不是 `0`：**让"个数 = top + 1"这条公式在任何时刻都成立**。

## 三、`push`：`++top` 必须是前置自增

```java
public void push(int value) {
    if (isFull()) {
        System.out.println("栈满，无法入栈");
        return;
    }
    stack[++top] = value;     // 先上移，再写进新空出来的那格
}
```

三种写法放一起看，只有一种是错的：

| 写法 | 等价形式 | 空栈时 push 第一个数（top = -1） | 结论 |
|---|---|---|---|
| `stack[++top] = value` | `top++; stack[top] = value;` | `top` 变 0，写进 `stack[0]` | ✅ 本代码用这个 |
| `top++; stack[top] = value;` | 同上 | 同上 | ✅ 完全等价，更好读 |
| `stack[top++] = value` | `stack[top] = value; top++;` | 写进 `stack[-1]` | ❌ `ArrayIndexOutOfBoundsException` |

**规律：`top` 指向"栈顶元素本身"，所以那个格子已经被占了，入栈必须先挪指针腾位置。** 前置自增（`++top`）是"先加后用"，后置自增（`top++`）是"先用后加" —— 这里需要的是"先用"那个空位，所以必须前置。

（对照 [环形队列.md](../queue/%E7%8E%AF%E5%BD%A2%E9%98%9F%E5%88%97.md)：那里 `rear` 定义成"下一个空位"，所以入队反而是 `arr[rear] = n; rear++`。**两根结构一样的代码，因为指针定义不同，先后顺序正好相反** —— 这类"语义决定写法"的对照，比背模板有用得多。）

## 四、`pop`：`top--` 必须是后置自增

```java
public int pop() {
    if (isEmpty()) {
        throw new RuntimeException("栈空，无法出栈");
    }
    return stack[top--];      // 先取当前格的值，再把指针退回去
}
```

| 写法 | 展开 | 取出的是 | 结论 |
|---|---|---|---|
| `return stack[top--]` | `v = stack[top]; top--; return v;` | 真正的栈顶 | ✅ |
| `return stack[--top]` | `top--; v = stack[top]; return v;` | **栈顶下面那个**（跳过了真正的栈顶） | ❌ 结果错位 |
| 写成 `top--; return stack[top];` | 同上 | 同上 | ❌ 同上 |

这是所有"取并前进"操作的通用铁律，第三次登场：

- 队列 `getQueue()`：`front++` 后 `return arr[front]` —— 因为 `front` 定义成"队头前一格"，所以先动后取。
- 链栈 `pop()`：`int value = oldTop.data; top = top.next;` —— 先取后动。
- **本代码 `pop()`：`stack[top--]` —— 先取后动。**

**看的是指针定义，不是模板。** 定义决定顺序，背模板必错。

另外 `pop` 只有一句 `return stack[top--]`，没有把 `stack[top]` 清 0：出栈后那一格的数据还躺着，但 `top` 已经退回，它不再属于栈。**下次 push 会直接覆盖它，所以数组版不需要担心残留。**（链栈版就必须 `oldTop.next = null`，见 [链栈.md](./%E9%93%BE%E6%A0%88.md) 第四节 —— 数组的格子会被复用，链表节点挂着引用会被一路拖住。）

## 五、数组栈天生没有"假满"，这才是它和数组队列的分水岭

[队列.md](../queue/%E9%98%9F%E5%88%97.md) 第五节的坑：数组队列出队后，`front` 前面的格子再也塞不进东西，因为**入队往右、出队也往右**，两根指针同向跑，中间的空洞永远够不着，只能靠环形取模（[环形队列.md](../queue/%E7%8E%AF%E5%BD%A2%E9%98%9F%E5%88%97.md)）补救。

```
   数组队列：进在右、出也在左→右，两根指针同向跑，中间出现永远够不着的空洞
   [作废][作废][ 3 ][ 4 ]        rear 顶到头 → 报"队列已满"，可 front 前面明明有空位
    ↑front          ↑rear

   数组栈：进在右、出也在右，只有一根指针来回搓
   push 4 → stack[3]=4; top=3
   pop    → top=2                     ← 3 号格立刻又变成可用
   push 5 → top=3, stack[3]=5          ← 同一格反复复用，永远不会"假满"
```

所以：

| | 数组队列 | 数组栈 |
|---|---|---|
| 需要环形/取模吗 | ✅ 需要（否则假满） | ❌ **完全不需要** |
| 真实容量 | `maxSize - 1`（环形版牺牲一格） | **`maxSize`，一格都不浪费** |
| 指针数量 | 2 | 1 |

**结论：栈是数组模拟里最省事的线性结构** —— 少一根指针、少一个特殊状态、不需要绕圈。代价是没有"队列的先进先出"能力（栈只能后进先出），两者不能互相替代。

## 六、`list`：从栈顶往栈底打印

```java
for (int i = top; i >= 0; i--) {
    System.out.println("stack[" + i + "]=" + stack[i]);
}
```

方向是 `top → 0`，即**栈顶在前、栈底在后**，符合"先看最上面"的直觉。实测（依次压入 1、2、3、4）：

```
stack[3]=4
stack[2]=3
stack[1]=2
stack[0]=1
```

注意它和 JDK `Stack.toString()` 的方向**正好相反**：`[jack, tom, jerry]` 是"栈底在左"（见 [栈.md](../linkedlist/%E6%A0%88.md) 第二节坑 2），而这里是从顶往下逐行打。两种都合理，但同一项目里对照着看时别搞混。

空栈时打印"栈空，无法遍历"（`void` 方法，直接提示即可，见第七节）。

## 七、异常与提示的分工（第三次用同一条规律）

```java
public void push(int value)   // void：满了没有结果要交回 → println + return
public int pop()              // 返回 int：空栈时返回哪个数都可能是真实数据 → throw
public void list()            // void：空栈打印一行提示 → return
```

判断标准还是 [队列.md](../queue/%E9%98%9F%E5%88%97.md) 第六节那条：**方法有没有返回值，决定它失败时该打印还是该抛异常**。`pop` 抛的 `RuntimeException` 由 `main` 里 `case "pop"` 的 `try-catch` 接住，打印 `e.getMessage()` 后继续回菜单，程序不崩（实测见第十一节）。

链栈 `LinkedStackDemo` 用的是同一套分工，所以两个栈的实现报错方式完全一致 —— 这正是"约定统一"的好处。

## 八、⚠️ 实测发现的四处可改进点（都是跑出来的，不是猜的）

### 1. 菜单里的 `list` 是个死选项（实测：输入后毫无反应）

`main` 打印了 5 行菜单，其中有 `list: 显示栈`，但 `switch` 里只有 `case "show" / "exit" / "push" / "pop"`：

```
输入 list 之后 —— 屏幕上除了重新出现的菜单，什么都没发生
```

`list` 落到 `default: break;`（空的）静默吞掉。而它和 `show` 的文案完全重复（"显示栈"），**修法二选一**：删掉菜单里的 `list` 这一行，或加 `case "list":` 和 `show` 共用一段逻辑（`case "show": case "list": stack.list(); break;`）。

### 2. `default` 不给任何提示

打错字（`shwo`、`List` 大写）会被完全静默，用户以为程序卡住。链栈版已经写了提示，这里对齐即可：

```java
default:
    System.out.println("输入指令有误，请重新输入");
    break;
```

### 3. `case "exit"` 没有 `scanner.close()`

```java
case "exit":
    loop = false;      // ← 只停循环，没关资源
    break;
```

`Scanner(System.in)` 关不掉第二次 `new`，练习程序无所谓，但和 [LinkedStackDemo.java](./LinkedStackDemo.java) 的 `exit` 分支（有关）对照着看，同一个项目里两种写法本身就是不一致。

### 4. 缺 `peek` 和 `size`

链栈版有 `peek()`/`size()`，数组版没有——而数组版做这两件事其实**最便宜**：

```java
public int peek() {
    if (isEmpty()) throw new RuntimeException("栈空，无法查看栈顶");
    return stack[top];              // 不移动 top，一眼就能看出和 pop 的差别
}

public int size() {
    return top + 1;                 // O(1) 白送；链栈要靠 count 字段才做到
}
```

这是第五节结论的另一面：**数组栈靠"下标天然是计数"省掉了链栈那个容易忘记同步的 `count` 字段**。

## 九、四种栈实现里它站在哪

只放定位，细表见 [栈.md](../linkedlist/%E6%A0%88.md) 附录与 [链栈.md](./%E9%93%BE%E6%A0%88.md) 第七节：

| | 数组栈（本代码） | 链栈 | JDK `Stack` | `ArrayDeque` |
|---|---|---|---|---|
| 容量 | **写死 `maxSize`** | 无上限 | 自动扩容 | 自动扩容 |
| 满的判断 | `top == maxSize - 1` | 不存在 | 不存在 | 不存在 |
| `size()` | O(1)（`top + 1`） | O(1)（靠 `count`） | O(1) | O(1) |
| 每元素额外开销 | 0（只有数组本体） | 一根 `next` + 对象头 | 一根引用 | 0 |
| 缓存友好度 | **最好**（连续） | 最差（散落） | 好 | 好 |
| 有没有"中间插入"后门 | 无（字段私有） | 无 | ⚠️ 有 | 无 |
| 空栈 `pop` | `RuntimeException`（自定义文案） | 同左 | `EmptyStackException` | `NoSuchElementException` |

一句选型建议：容量能估准 → 数组栈（本代码这种）；估不准或根本不知道多深（表达式求值、递归模拟）→ 链栈；生产代码 → `ArrayDeque`。

## 十、复杂度总账

| 操作 | 时间 | 说明 |
|---|---|---|
| `push` | **O(1)** | 判满 + `++top` + 一次赋值 |
| `pop` / `peek` | **O(1)** | 一次赋值 + `top--` |
| `isEmpty` / `isFull` / `size` | **O(1)** | 纯算式 |
| `list` | O(n) | 全遍历 |
| 空间 | O(maxSize) | **一格都不浪费**（不像环形队列要牺牲一格） |

## 十二、一句话记住数组栈

> **数组栈只有一根 `top` 指针，它指着"栈顶元素本身"，所以空栈是 `-1`（让 `个数 = top + 1` 永远成立）、判满是 `top == maxSize - 1`；入栈必须先动指针再写值（`stack[++top] = x`），出栈必须先取值再退指针（`stack[top--]`），前后置自增写反就分别越界和错位；出栈不擦数据、下次覆盖即可，因此数组栈天生没有队列那种"假满"，也不需要环形取模，容量一格不浪费；失败处理照旧：`void` 的 push/list 打印提示，有返回值的 pop/peek 抛异常由 main 捕获。**

## 十三、往下学什么

1. **补上第八节的四处**：`case "list"`、`default` 提示、`scanner.close()`、`peek()`/`size()` —— 都是三五行的事，补完这一版就和链栈的接口对齐了。
2. **做成能扩容的栈**：满的时候 `Arrays.copyOf(stack, maxSize * 2)` 再把 `maxSize` 翻倍，理解"均摊 O(1)"这个词从哪来（JDK `Stack`/`Vector` 内部就是这个套路）。
3. **泛型化**：把 `int` 换成 `<T>` + `T[]`（注意泛型数组不能直接 `new T[n]`，得 `(T[]) new Object[n]`），对照 JDK `Stack<E>` 的签名。
4. **用它写括号匹配**（LeetCode 20）：左括号入栈，右括号 `pop` 出来配对 —— 第一次真正用上自己的 `pop` + `isEmpty`。
5. **用它写双栈计算器**：本目录的 [Calculator.java](./Calculator.java) 就是这道题（数栈 + 符号栈），`peek()` 已补上、**现在能编译能跑，但结果还是错的**（`3+2*6-2` 得 2，应为 13）：运算符分支只处理了"能算时算一次"，**没把新运算符入栈**（优先级不够时它直接丢了），而正确的应该是"能算就一直算（`while`），算完无条件 `push(ch)`"。另外它的 `peek()` 也没判空，`top == -1` 时会抛 `Index -1 out of bounds`。等它跑通再单独写一篇计算器笔记。

# 双栈中缀计算器（数栈 + 符号栈）

> 对应程序：[Calculator.java](./Calculator.java)（内含 `ArrayStack2`）
> 另一条路线的兄弟篇：[逆波兰计算器.md](./%E9%80%86%E6%B3%A2%E5%85%B0%E8%AE%A1%E7%AE%97%E5%99%A8.md) —— 那份是"先翻译成后缀再算"，这份是"一边扫描一边算"。
> 栈本身的原理见 [数组栈.md](./%E6%95%B0%E7%BB%84%E6%A0%88.md)。

---

## 一、两条路线，同一个问题

要算 `3+2*(6-2)`，难点只有两个：**优先级**（先乘除后加减）和**括号**（括号里先算）。

| | 双栈中缀（本篇 `Calculator`） | 逆波兰（`PolandNotation` / `ReversePolishCalculator`） |
|---|---|---|
| 思路 | 扫一遍字符串，能算的当场算掉 | 先把中缀翻译成后缀，再算后缀 |
| 需要几个栈 | 2 个（数栈 + 符号栈），扫描时同时用 | 翻译阶段 1 个符号栈，求值阶段 1 个数栈（分两步） |
| 优先级怎么处理 | 遇到运算符时，跟栈顶比大小，不低于自己就先算 | 在翻译阶段就消化掉了，求值时**完全不用管优先级** |
| 括号怎么处理 | `(` 入栈当分界线，`)` 触发一路结算 | 同样在翻译阶段消化（`)` 弹到 `(` 为止） |
| 中间结果能不能看 | 看不到，只有最终结果 | 能打印出后缀式，便于核对 |
| 代码量 | 一个主循环搞定 | 分词 + 翻译 + 求值三步 |

一句话概括差别：**双栈版是"边算边压"，逆波兰版是"先翻译后计算"**。学习阶段两个都值得写一遍，因为逆波兰那条路能让你看清"优先级和括号本质上是栈的调度问题"。

## 二、两个栈，各管一件事

```java
ArrayStack2 numStack = new ArrayStack2(10);       // 数栈：存数字（10 是栈容量，不是表达式长度）
ArrayStack2 operatorStack = new ArrayStack2(10);  // 符号栈：存运算符和左括号
```

`ArrayStack2` 就是 [数组栈.md](./%E6%95%B0%E7%BB%84%E6%A0%88.md) 里那个数组栈（`top = -1`、`stack[++top] = v`、`stack[top--]`），另外多带三个"其实跟栈无关"的方法：`priority`（优先级）、`isOperator`（是不是运算符）、`cal`（算一个表达式）。它们不读写 `stack`/`top`，挂在这里只是为了少建一个类 —— 严格说该做成 `static`，见第九节。

```
   扫描 3 + 2 * ( 6 - 2 ) 的过程中，两个栈的状态：

   扫到 '3'          numStack [3]                    operatorStack []
   扫到 '+'          numStack [3]                    operatorStack [+]        栈空，直接入栈
   扫到 '2'          numStack [3,2]                  operatorStack [+]
   扫到 '*'          numStack [3,2]                  operatorStack [+,*]      priority(*)>priority(+)，不结算，入栈
   扫到 '('          numStack [3,2]                  operatorStack [+,(,*]    左括号直接入栈
   扫到 '6'          numStack [3,2,6]                operatorStack [+,(,*]
   扫到 '-'          numStack [3,2,6]                operatorStack [+,(,-,*]
   扫到 '2'          numStack [3,2,6,2]              operatorStack [+,(,-,*]
   扫到 ')'          结算到 '(' 为止：6-2=4
                     numStack [3,2,4]                operatorStack [+,*]      左括号被丢弃
   扫描结束          符号栈清空结算：2*4=8 → 3+8=11
                     numStack [11]
```

**读图要点**：数栈里永远存放"还没被用掉的数字"，符号栈存放"欠着的运算"。每当一个运算的两个操作数都齐了、且它的优先级不允许再等，就立刻结算，结果压回数栈当新操作数。

## 三、主循环的五类分支

```java
while (index < expression.length()) {
    ch = expression.charAt(index);
    if (ch == '(') {                 // ① 左括号：直接入符号栈
        bracket++; operatorStack.push(ch);
    } else if (ch == ')') {          // ② 右括号：一路结算到左括号
        ...
    } else if (operatorStack.isOperator(ch)) {   // ③ 运算符：比优先级
        ...
    } else if (ch >= '0' && ch <= '9') {         // ④ 数字：往后拼成多位数
        ...
    } else {                                     // ⑤ 其他字符：报错退出
        ...
    }
    index++;
}
while (!operatorStack.isEmpty()) { /* ⑥ 收尾结算 */ }
System.out.println("... 结果是 " + numStack.peek());
```

顺序很关键：**括号判断必须排在 `isOperator` 前面**。因为 `isOperator` 只认 `+ - * /`，把 `(` `)` 单独列在前面两类处理是对的；但如果你哪天把 `(` 也塞进 `isOperator`，那 ③ 就会抢在 ① 之前命中，括号逻辑全部失效。

## 四、运算符分支：为什么 `if` 在这里够用（但 `while` 更稳）

现在的写法是"三分支"：

```java
if (!operatorStack.isEmpty()) {
    if (priority(ch) <= priority(operatorStack.peek())) {
        结算一次;                     // 弹两个数、弹一个运算符、算完压回数栈
        operatorStack.push(ch);      // ★ 结算完，新运算符还是要入栈
    } else {
        operatorStack.push(ch);      // 优先级更高，压着等
    }
} else {
    operatorStack.push(ch);          // 栈空，直接入栈
}
```

三处的 `push(ch)` 一次都没落下 —— 这就是之前那版"只在栈空时 push"的 bug 修法（漏掉的话 `2*(3+4` 这种会丢运算符，实测结果从 19 变 2）。

**为什么用 `if` 结算一次就够？** 因为这段代码维持着一个不变式：**符号栈从底到顶，优先级严格递增**。既然栈顶是唯一可能"不低于新运算符"的位置，弹掉它之后，新的栈顶优先级必然更低，不可能还要再结算。所以 `if` 和 `while` 在这里结果相同。

但 `while` 版本更好，理由不是正确性而是**可读性和抗改动**：

```java
while (!operatorStack.isEmpty()
        && operatorStack.peek() != '('
        && priority(ch) <= priority(operatorStack.peek())) {
    结算一次;
}
operatorStack.push(ch);      // 只写一次，不用在三个分支里各写一遍
```

- 不需要读者先想出"栈内严格递增"这个不变式才敢确信 `if` 够；
- 三处 `push(ch)` 收成一处，改代码时不会漏（这正是之前那个 bug 的成因）；
- 万一以后加了 `^`（幂，右结合）这类需要多层结算的运算符，`while` 不用改。

## 五、括号为什么能生效：靠的是 `priority('(') = -1`

```java
public int priority(int operator) {
    if (operator == '*' || operator == '/') return 1;
    else if (operator == '+' || operator == '-') return 0;
    else return -1;          // ← 左括号落到这里
}
```

三个点配合起来，括号才起作用：

1. **`(` 入栈但不参与比较**：遇到 `(` 直接压栈，不结算任何东西。
2. **`(` 优先级最低（-1）**：栈顶是 `(` 时，`priority(ch) <= priority('(')` 恒为假 → 括号内部的运算符只往栈里叠，**绝不会被括号外面的运算符提前结算**。这就是 `3 + (2 * 4)` 里 `+` 不会抢先把 `2` 拉走的原因。
3. **`)` 触发一路结算**：`while (peek() != '(') { 结算 }`，然后 `pop()` 丢掉 `(`。这里**必须是 `while`**，因为 `2*(3+4+5)` 的括号里可能压着两个运算符。

多层嵌套也天然成立：`2*(3+4*(5-3))` 实测 = **22**（`5-3=2 → 4*2=8 → 3+8=11 → 2*11=22` ✓），靠的就是栈里叠了两个 `(`，第一个 `)` 只结算到最近的那个 `(`。

括号配对用 `bracket` 深度计数在三个地方把关（实测）：

```
3+2)*4   → 括号不匹配：第 3 位的 ')' 找不到对应的左括号     （--bracket < 0）
3*(2+4   → 括号不匹配：缺少右括号                          （扫描完 bracket != 0）
```

第二处校验为什么必须有：少了它，收尾结算会把 `(` 当运算符传给 `cal`，`switch` 四个 case 一个都不匹配，`res` 保持 0 **默默压回数栈** —— 得到一个看起来正常的错答案。

## 六、多位数：lookahead 的条件只能是"还是数字"

```java
keepNum = "" + ch;
while (index + 1 < expression.length()
        && expression.charAt(index + 1) >= '0'
        && expression.charAt(index + 1) <= '9') {   // ★ 只认数字
    keepNum += expression.charAt(++index);
}
numStack.push(Integer.parseInt(keepNum));
```

这里踩过一个坑，注释里也写着：**条件不能写成 `!isOperator(下一位)`**。因为 `(` `)` 不属于 `isOperator`，那样会把右括号当成"数字的一部分"拼进去 —— 算 `(3+2)*4` 时扫到 `2`，下一位是 `)`，`keepNum` 变成 `"2)"`，`Integer.parseInt("2)")` 直接抛 `NumberFormatException`。

判断"是不是数字的一部分"和"是不是运算符"是**两个不重叠的集合**，中间还有括号、小数点、空格这些第三种情况。写解析逻辑时，宁可正向判断"我要什么"（是数字），也别反向判断"我不要什么"（不是运算符）。

## 七、实测结果汇总

正常用例（全部实跑）：

| 表达式 | 输出 | 说明 |
|---|---|---|
| `(3+2)*4-1`（默认） | `结果是 19` | 括号 + 优先级 |
| `10-2*3` | `结果是 4` | 多位数 |
| `2*(3+4*(5-3))` | `结果是 22` | 多层嵌套 |
| `3*(2+4` | `括号不匹配：缺少右括号` | 校验生效 |
| `3+2)*4` | `括号不匹配：第 3 位的 ')' 找不到对应的左括号` | 校验生效 |
| `((((((((((1+2` | `栈满，无法入栈` → `括号不匹配：缺少右括号` | 见第八节 |

会直接崩掉的输入（**未捕获异常**，实测）：

| 表达式 | 异常 | 崩在哪 |
|---|---|---|
| `5/(3-3)` | `java.lang.ArithmeticException: / by zero` | `Calculator.java:98`（`cal` 里的除法） |
| `3+2*` | `java.lang.RuntimeException: 栈空，无法出栈` | `Calculator.java:96`（收尾结算拿不到两个数） |

## 八、已知局限（四条，都有实测依据）

1. **只支持整数**：`numStack` 是 `int[]`，`Integer.parseInt`。写 `3.5*2` 会走"非法字符"分支报 `表达式含非法字符：'.'`。要支持小数得把栈换成 `double[]`（[逆波兰计算器.md](./%E9%80%86%E6%B3%A2%E5%85%B0%E8%AE%A1%E7%AE%97%E5%99%A8.md) 那两份就是 `double`）。
2. **栈容量写死 10，而且"栈满"只打印不中断**：`push` 里 `if (isFull()) { println("栈满，无法入栈"); return; }` —— 数据没进栈，但流程继续往下跑，后面 `pop` 拿到的是错位的数。实测 `((((((((((1+2` 就触发了它（这次侥幸被括号校验拦住并退出，换个表达式就可能给出错答案）。**"提示一句继续跑"是比抛异常更危险的处理方式**，至少要 `return` 掉主流程。
3. **除零、表达式不完整都是裸崩溃**：`5/(3-3)`、`3+2*` 直接把堆栈甩在屏幕上（见第七节表）。要能用，得在 `cal` 里判 `num1 == 0`、在结算前判 `numStack` 里有几个数。
4. **不支持一元负号**：`-3+2` 会被当成"缺左操作数的减号"。真要做，得在分词阶段判断"这个位置该出现数字还是运算符"，把 `-3` 整体识别成一个数（`ReversePolishCalculator` 也没做，理由一致：加了会明显变复杂）。

另外一个代码整洁度问题：`priority` / `isOperator` / `cal` 三个方法完全不碰 `stack`、`top`、`maxSize`，本质是工具方法，挂在 `ArrayStack2` 上导致出现 `numStack.cal(...)`（用**数栈**去调**计算**）、`operatorStack.isOperator(ch)` 这种读起来别扭的调用。它们应该是 `static`，或者干脆抽成 `ExpressionUtils`。

## 十、一句话记住双栈计算器

> **一个数栈放"还没用掉的数"，一个符号栈放"欠着的运算"；扫到数字就往后拼成多位数（lookahead 只能认数字，不能认"不是运算符"），扫到运算符就把栈里优先级不低于它的当场结算、然后自己入栈，扫到 `(` 就压一条分界线（靠 `priority('(') = -1` 挡住外部结算），扫到 `)` 就一路结算到那条线为止并把线丢掉，扫描结束把符号栈清空结算 —— 结果就是数栈栈顶。**

## 十一、往下学什么

1. **[逆波兰计算器.md](./%E9%80%86%E6%B3%A2%E5%85%B0%E8%AE%A1%E7%AE%97%E5%99%A8.md)**：同一道题的另一条路，做完对照你会明白"优先级和括号"其实是可以在**翻译阶段**一次性消化掉的。
2. **补掉第八节那四条**：换 `double`、栈满时中断、除零与缺操作数给友好提示、支持一元负号。
3. **加 `%` 和 `^`**：`priority` 加一级即可，但 `^` 是**右结合**（`2^3^2 = 2^9`），这时 `<=` 要改成 `<`，正好检验你第四节那个不变式还成不成立。
4. **加函数调用**（`max(1,2)`、`sin(30)`）：符号栈里要记函数和参数分隔符 `,`，是编译器前端的最小模型。

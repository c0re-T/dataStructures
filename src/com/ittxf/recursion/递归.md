## 一、递归的两件事：调用 + 回归

递归最容易搞错的不是"怎么调下去"，而是**"什么时候回来执行剩下的代码"**。

```
   方法调用一次 = 在栈上开一个新栈帧（有自己的参数 n、自己的局部变量、自己的执行位置）
   方法返回一次 = 那个栈帧弹出，回到调用它的那一行接着往下走

   test(5) 里写着"先递归 test(4)，再打印"，所以打印这件事发生在回归的路上，
   而不是发生在往下调的时候 —— 这就是输出顺序 2,3,4,5 的全部原因
```

**重要规则**（这四条能解释 90% 的递归 bug）：

1. 递归必须**给出明确的跳出条件**（`if (n > 2)`、`if (n == 1)`），否则无限调下去 → `StackOverflowError`。
2. 每次递归调用，传递给变量的值必须是**趋向跳出条件**的（`n - 1`），写成 `n + 1` 就永远出不来。
3. 每次执行一个方法都会开辟新的栈帧，所以递归"同时存在"很多份 `n`，各栈帧里的 `n` 互不干扰。
4. 栈帧使用完毕（方法返回）就弹出归还，**它的局部变量随之消失**（这也是为什么递归的结果要靠返回值带回来，不能指望上一层看见你的局部变量）。

## 二、`test(5)`：为什么打印顺序是 2 3 4 5

```java
public static void test(int n) {
    if (n > 2) {
        test(n - 1);
    } /*else {
        System.out.println("n = " + n);
    }*/
    // 不加 else 语句，程序会根据开辟栈的顺序，依次打印 n = 2, n = 3, n = 4, n = 5
    System.out.println("n = " + n);
}
```

实测输出：

```
n = 2
n = 3
n = 4
n = 5
```

按栈帧的变化走一遍（左边是栈底，`▶` 是正在执行的那一帧）：

```
   ① main 调 test(5)
      [ ▶test(5) ]                      n=5 > 2 → 先进去递归，还没打印

   ② test(5) 里调 test(4)
      [ test(5) ][ ▶test(4) ]           同样先递归

   ③ test(4) → test(3)
      [ test(5) ][ test(4) ][ ▶test(3) ]

   ④ test(3) → test(2)
      [ test(5) ][ test(4) ][ test(3) ][ ▶test(2) ]

   ⑤ test(2)：n > 2 不成立 → 不再递归 → 直接执行 println
      打印 n = 2                         ← 第一个被打印的是最深的那一层
      然后 test(2) 返回，弹出栈帧

   ⑥ 回到 test(3) 里"test(n-1)"的下一行，也就是 println
      打印 n = 3                         ← 回归一层，打印一个
   ⑦ 回到 test(4) → 打印 n = 4
   ⑧ 回到 test(5) → 打印 n = 5
```

**一句话记住：往下调的时候什么都不做，往回返的时候才打印 —— 所以顺序是"最深的最先"，正好是 2→3→4→5。**

代码里那段被注释掉的 `else` 是关键对照：

| 写法 | 打印时机 | 输出 |
|---|---|---|
| 现在这样（`println` 在 `if` 之后，无 else） | 每帧回归时打印 | `2 3 4 5`（先深后浅） |
| 用 `else { println }` | 只有 `n <= 2` 那一帧才打印，且是在往下走时 | 只有一行 `n = 2` |
| 把 `println` 挪到 `if (n > 2)` **之前** | 每帧进入时立刻打印 | `5 4 3 2`（先浅后深） |

**同样一句 `System.out.println("n = " + n)`，放在递归调用之前还是之后，输出顺序正好相反。** 这是递归最基础也最容易写反的一件事，后面迷宫回溯、八皇后找解，靠的全是这个"回来时再处理"的能力。

## 三、`factorial(2)`：递归要有"返回值"才能把结果带回来

```java
public static int factorial(int n) {
    if (n == 1) {
        return 1;                    // 跳出条件：1! = 1
    } else {
        return n * factorial(n - 1); // 2 * 1!
    }
}
```

实测 `factorial(2)` 输出 `res = 2`。展开看它的"递"和"归"：

```
   递（一路往下问）
   factorial(2) = 2 * factorial(1)
   factorial(1) = 1        ← 命中跳出条件，开始往回带值

   归（一路把结果带回）
   factorial(1) 返回 1
   factorial(2) = 2 * 1 = 2 ← 结果靠 return 一层层往上送

   对比 test(n)：它是 void，打印完就结束，不需要往回带值
   阶乘必须带值，所以每一层都得写 return n * factorial(n-1)
   如果漏写 return（比如最后一行写成 factorial(n-1) 不接值），编译就过不去
```

代码末尾那行被注释的 `// return n * factorial(n - 1);` 是作者留的另一种写法：把它放开、去掉 `if-else`，就得**在方法开头先判 `n == 1` 并 return**，否则永远递归下去。两种写法等价，区别只是跳出条件写在前面还是包在 `if-else` 里。

## 四、递归的代价：栈帧不是免费的

| | 递归 | 循环 |
|---|---|---|
| 每次调用的开销 | 开栈帧（存参数、局部变量、返回地址） | 只有变量自增 |
| 深度上限 | 受栈大小限制，太深就 `StackOverflowError` | 无深度概念 |
| 代码 | 常常短得多、贴近人的思路 | 要自己维护状态 |

两个必须知道的坑：

- **`StackOverflowError`**：递归没有跳出条件、或者跳出条件永远等不到（比如 `factorial(0)`：`0 == 1` 不成立，于是 `factorial(-1)`、`factorial(-2)`……一路减到栈爆）。**写递归先写跳出条件，再想边界值能不能命中它。**
- **`int` 溢出比栈先炸**：`factorial(13) = 6227020800`，已经超过 `int` 上限 `2147483647`，所以 `factorial(20)` 不会栈溢出，而是**安安静静给你一个错的数**。递归算阶乘、斐波那契时，先想清楚类型够不够（`long` 到 `20!`），这比栈深更常踩。

顺带把 [栈.md](../linkedlist/%E6%A0%88.md) 里那句话接上：**函数调用栈就是操作系统给你的一串栈帧**，本篇画的那个"栈帧一层层压上去"的图，和调试器里看到的 call stack 是同一个东西；异常栈 `at xxx.java:21` 从上往下读，就是这张图从 `▶` 那层往栈底读。

## 五、动手验证剧本

```powershell
javac -encoding UTF-8 -d out src\com\ittxf\recursion\RecursionTest.java
java -cp out com.ittxf.recursion.RecursionTest
```

基准输出（实跑）：

```
===================打印问题===================
n = 2
n = 3
n = 4
n = 5
===================阶乘问题===================
res = 2
```

改四处，把"调用与回归"这件事彻底钉死：

| 实验 | 怎么改 | 会看到什么 | 印证哪一节 |
|---|---|---|---|
| 1 | 把 `test(5)` 改成 `test(2)` | 只打印一行 `n = 2`（第一层就不满足 `n > 2`，直接打印返回） | 第二节规则 2 |
| 2 | 把 `println` 挪到 `if (n > 2)` 之前 | 输出变成 `5 4 3 2` | 第二节对照表 |
| 3 | 把 `else` 那段注释放开、同时删掉外面的 `println` | 只剩 `n = 2` 一行 | 第二节对照表 |
| 4 | `factorial(0)` | 抛 `StackOverflowError`（`0 == 1` 永不成立，一路 `-1` 下去） | 第四节 |
| 5 | `factorial(20)` 并打印结果 | 得到一个不合常理的数（`int` 溢出），而不是报错 | 第四节 |

第 4、5 条是"递归最典型的两种死法"：一种炸得轰轰烈烈，一种静默给你错答案 —— 后者更难查。

## 六、一句话记住递归

> **每次调用都开一个新栈帧，参数 `n` 在这一帧里是私有的；把代码写在递归调用之前，是"往下走时执行"，写在之后，是"往回返时执行"—— 这一前一后就是回溯的全部机关；跳出条件必须明确且能被命中，返回值要一层层带上来，而栈深和 `int` 范围是两条不同的红线。**

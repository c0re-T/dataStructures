## 一、问题与最关键的一步：用一维数组表示棋盘

在 8×8 棋盘上放 8 个皇后，任意两个不能同行、同列、同对角线。

直觉会想开 `int[8][8]` 二维数组，但代码里只用了一个一维数组：

```java
int[] array = new int[max];
// 约定：array[行] = 列
// 例如 array = {0, 4, 7, 5, 2, 6, 1, 3}
//   表示第 0 行的皇后放在第 0 列，第 1 行的皇后放在第 4 列……
```

```
   array = {0, 4, 7, 5, 2, 6, 1, 3}  对应的棋盘（▼ 是皇后）

   行\列  0   1   2   3   4   5   6   7
   行0    ▼                               ← array[0] = 0
   行1                ▼                   ← array[1] = 4
   行2                                ▼   ← array[2] = 7
   行3                        ▼           ← array[3] = 5
   行4            ▼                       ← array[4] = 2
   行5                    ▼               ← array[5] = 6
   行6        ▼                           ← array[6] = 1
   行7            ▼                       ← array[7] = 3
```

**为什么一维就够**：因为算法是**逐行放置**的 —— 第 `n` 行只放一个皇后（放完就递归去第 `n+1` 行）。既然"每行恰好一个"是构造过程保证的，那么每行只需要记住"那个皇后在哪一列"。

这一步建模的直接收益：**同行冲突根本不需要判断**（一行就一个），检查项从三个变两个。

## 二、三个方法的分工

```java
place(n)    放第 n 行的皇后；n == max 说明 8 行都放完了 → 找到一个解
judge(n)    第 n 行刚放好，回头检查它跟前面 0..n-1 行有没有冲突
print()     把一个解（array 的内容）打印出来，并 count++
```

`place` 的骨架就是标准的递归三段：

```java
private void place(int n) {
    if (n == max) {        // ① 跳出条件：8 行都放好了
        print();           //    找到一个解
        return;
    }
    for (int i = 0; i < max; i++) {   // ② 第 n 行依次试第 0..7 列
        array[n] = i;                 //    放！
        if (judge(n)) {               // ③ 不冲突才往下走
            place(n + 1);             //    去放下一行
        }
        // 冲突 or 下面的行全试过 → 直接进入下一轮 for，array[n] 被覆盖成新列
    }
}
```

调用链长这样（`main` 里只有一句 `queen8.place(0)`）：

```
   place(0) ─ array[0]=0 → judge ✓ → place(1) ─ array[1]=0 ✗(同列) → =1 ✗(对角) → =2 ✗ → =3 ✗ → =4 ✓ → place(2) ...
                                                            ↑ 每一层都有自己的 for 循环和 i，
                                                              这些"第几列试到哪了"就存在各自的栈帧里
```

**关键理解**：`for` 循环里的 `i` 是**每层栈帧私有的**。第 3 层试到 `i=5` 时，第 2 层的 `i` 还稳稳停在它刚才的值上（在栈帧里睡着），等第 3 层返回，第 2 层继续 `i++`。这就是 [递归.md](./%E9%80%92%E5%BD%92.md) 第三节说的"每个栈帧有自己的局部变量"。

## 三、`judge` 的两个条件（第三个条件白送）

```java
private boolean judge(int n) {
    judgeCount++;
    for (int i = 0; i < n; i++) {
        if (array[i] == array[n]                                       // ① 同一列
                || Math.abs(n - i) == Math.abs(array[n] - array[i])) { // ② 同一对角线
            return false;
        }
    }
    return true;
}
```

| 冲突类型 | 判断式 | 说明 |
|---|---|---|
| 同一行 | **不用判** | 每行只放一个，是 `place` 逐行递归天然保证的 |
| 同一列 | `array[i] == array[n]` | 两行的列号相同 |
| 同一对角线 | `Math.abs(n - i) == Math.abs(array[n] - array[i])` | **行距 == 列距** |

对角线那个式子为什么成立：

```
   ↘ 主对角线方向：每往下一行，列号也 +1（或 -1），所以行距恒等于列距
   行\列  0   1   2   3
   0      A                       (0,0) 与 (1,1)：|1-0| = |1-0| = 1 ✓ 冲突
   1          B                   (0,0) 与 (2,2)：|2-0| = |2-0| = 2 ✓ 冲突
   2                              (0,0) 与 (2,1)：|2-0| = 2，|1-0| = 1 ✗ 不冲突

   ↗ 副对角线方向：往下一行，列号 -1，绝对值一取同样成立
   行\列  0   1   2   3
   0                  A           (0,3) 与 (1,2)：|1-0| = |2-3| = 1 ✓ 冲突
   1              B
```

一个 `if` 里用 `||` 合并两个条件，是这段代码最容易被看不懂的地方 —— 拆开看就是"同列 或 同行距等列距"。

## 四、实测数据（跑 `Queen8` 的输出）

```
0	4	7	5	2	6	1	3      ← 第 1 个解
0	5	7	2	6	3	1	4      ← 第 2 个解
...
一共有92种解法
判断次数为15720
```

`92` 是八皇后的经典答案（如果只算"去掉旋转/镜像对称"的基本解，是 12 个）。

**不同棋盘大小的实测增长**（我用一个临时探针跑 `Queen8` 同一套逻辑得到的数字，探针已删）：

| N（棋盘） | 解法数 | `judge` 调用次数 | `place` 调用次数 |
|---|---|---|---|
| 1 | 1 | 1 | 2 |
| 2 | 0 | 6 | 3 |
| 3 | **0** | 18 | 6 |
| 4 | **2** | 60 | 17 |
| 5 | 10 | 220 | 54 |
| 6 | 4 | 894 | 153 |
| 7 | 40 | 3584 | 552 |
| **8** | **92** | **15720** | **2057** |
| 9 | 352 | 72378 | 8394 |
| 10 | 724 | 348150 | 35539 |

三个值得停下来看的点：

1. **3 个皇后无解**（0 个），4 个才有 2 个解。所以别以为"棋盘越小越好算"，小棋盘反而可能直接无解。
2. **6 皇后只有 4 个解，比 5 皇后的 10 个还少** —— 解的数量不是单调涨的，这类组合问题的数字经常反直觉。
3. **N 从 8 涨到 10，判断次数从 1.5 万涨到 35 万（×22）**，指数级。这就是为什么八皇后往上到 20 皇后时，纯回溯就不够用了，需要位运算、对称性剪枝甚至专用算法。

## 五、回溯在哪里？—— 这个版本的回溯是"隐形"的

对比迷宫，很有意思：

```java
// 迷宫（MazeShortestPath）：必须显式擦掉标记
map[i][j] = 2;
... 递归四个方向 ...
map[i][j] = 0;      // ★ 不写这句，后面的路径就被堵死

// 八皇后（Queen8）：没有任何"撤销"语句
array[n] = i;
if (judge(n)) place(n + 1);
// for 循环下一轮，array[n] 直接被新的 i 覆盖 —— 覆盖就是撤销
```

为什么八皇后可以不写撤销？

- `array` 的语义是"**第 n 行**的皇后在第几列"，`judge(n)` 只遍历 `i < n`，**永远只看比当前行号小的那些行**。
- 所以当第 5 行试完、退回第 4 行继续试下一列时，第 5、6、7 行里残留的旧值**根本不会被读到**，脏不脏无所谓。
- 而迷宫的标记是"这个格子被占用"，写在共享地图上，谁都读 —— 不擦就会挡住后面的路径。

**结论：要不要显式撤销，取决于"这个状态会不会被别人读到"。** 这是回溯最容易写错（也最容易写多余）的地方。

不过 `array` 长度只有 `max`，第 8 行的残留值虽然不影响正确性，但会让"当前数组快照"看起来像有 8 个皇后 —— 所以动画里我只把 `0..n-1` 行画成已确定，第 `n` 行画成"正在试"。

## 六、`judge` 就是剪枝（一个实测证明）

`judge` 一旦返回 `false`，`place(n+1)` 就不执行 —— 这一整棵子树被砍掉，这就是**剪枝**。砍得狠不狠，用数字说话：

| 做法 | 解法数 | 说明 |
|---|---|---|
| 不剪枝（每个位置都试到底） | — | `8^8 = 16777216` 种摆法 |
| 只判同列，**漏掉对角线** | **40320**（实测） | 恰好等于 `8!`：每行不同列的全排列数 |
| 同列 + 对角线都判（正确写法） | **92**（实测） | 完整剪枝 |
| 完全不判断，随机摆 8 个子 | 期望 0 | 连一个合法解都碰不到 |

我特意跑了一版"只判同列"的：解法数正好是 **40320 = 8!** —— 说明"每行不同列"这一层只把 `8^8` 砍到 `8!`（约 416 倍），而**对角线判断才是把 40320 砍到 92 的那一刀**（约 438 倍）。少写一个条件，结果不是"错一点"，而是数量级的差别，而且**它不报错**，只是安安静静给你 40320 个"解"，其中绝大多数两个皇后互相能吃掉。

## 七、怎么读一个解

`print()` 打印的是 `array` 本身，不是棋盘：

```
0	4	7	5	2	6	1	3
```

读法：**下标是行，值是列**。

```
   array[0]=0 → 皇后在 (0,0)      array[4]=2 → 皇后在 (4,2)
   array[1]=4 → 皇后在 (1,4)      ...
```

想打印成棋盘，就再套一层循环（这也是动画里棋盘渲染做的事）：

```java
for (int row = 0; row < max; row++) {        // 逐行
    for (int col = 0; col < max; col++) {    // 逐列
        System.out.print(array[row] == col ? "Q " : ". ");
    }
    System.out.println();
}
```

## 九、一句话记住八皇后

> **逐行放皇后，所以一个一维数组 `array[行] = 列` 就装下了整个棋盘，同行冲突白送不用判；`place(n)` 里 `array[n] = i` 是"放"、`judge(n)` 是"查有没有跟前面几行撞列或撞斜线（行距 == 列距）"、`place(n+1)` 是"往下走"，for 循环的下一个 `i` 就是回溯（覆盖即撤销，因为 `judge` 只看比当前行号小的行）；`judge` 是剪枝，砍掉对角线判断会让解从 92 变成 40320 = 8!，而且不报错。**

## 十、往下学什么

1. **打开 [八皇后动画.html](./%E5%85%AB%E7%9A%87%E5%90%8E%E5%8A%A8%E7%94%BB.html)**，把棋盘调到 4，用"单步"走完一遍：你会看到 `place(0)→place(1)→…` 的调用栈怎么涨缩、`judge` 什么时候红、回溯时哪一格被换掉。
2. **给 `print()` 加棋盘渲染**（第七节那段代码），92 个解每个都画出来。
3. **N 皇后位运算版**：用三个 `int` 分别记录"被占用的列 / 左斜线 / 右斜线"，`place` 里用 `bits & ~(cols|diag1|diag2)` 直接拿到可放位置 —— N=14 以上时比数组版快一个数量级。
4. **数独求解器**：跟八皇后是同一个骨架（选格子 → 试数字 → 检查冲突 → 递归 → 撤销），只是"候选集"从 8 列变成 1~9。
5. **回溯的通用模板**：`路径 + 条件 + 选择`，把迷宫、八皇后、全排列、组合总和放一起看，你会发现只有"怎么判断冲突"和"要不要显式撤销"两处不同。

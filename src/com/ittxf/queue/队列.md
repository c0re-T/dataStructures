# 队列（用数组模拟）

> 对应程序：[ArrayQueueDemo.java](./ArrayQueueDemo.java)
> 一个类里塞了两样东西：`ArrayQueueDemo`（main + 菜单交互）负责「用」队列，`ArrayQueue`（数组实现）负责「是」队列。

---

## 一、队列到底是个啥

一句话：**排队的窗口，先来先办事，后来靠边站**。

- 只能从**尾巴**塞进去（入队 `addQueue`）
- 只能从**头**取出来（出队 `getQueue`）
- 规矩叫 **FIFO**（First In First Out，先进先出）

跟生活对一下：取票机打出来的票、餐厅等位叫号、打印任务、消息队列、BFS 的待办清单，全是队列。

```
   出队 ◄──── ┌─────┬─────┬─────┬─────┐ ────► 入队
   （头部）   │  1  │  2  │  3  │     │    （尾部）
             └─────┴─────┴─────┴─────┘
              front ↑              ↑ rear
           （头的前一格）      （最后一个元素）

   最先进来的 1，必须第一个出去；3 虽然最后进来，也只能排在 2 后面
```

对比一下栈（Stack，见 [栈.md](../linkedlist/%E6%A0%88.md)）：栈是「一摞盘子」，最后放上去的最先拿（LIFO）；队列是「一根水管」，水从头进尾出。这俩是最容易混的一对。

## 二、这份代码里的三个核心变量

```java
private int maxSize;  // 数组最多能放几个
private int front;    // 队列头
private int rear;     // 队列尾
private int[] arr;    // 真正存数据的数组
```

`maxSize` 决定数组长度，`arr` 是货架，`front` 和 `rear` 是**两个游标（下标）**，它们不动数据，只是「指」着数据。**搞懂队列 = 搞懂这两个指针指在哪。**

### 关键设计：front 和 rear 各指哪儿？

构造函数里写死了：

```java
this.front = -1;  // 指向队列头【的前一个位置】
this.rear = -1;   // 指向队列尾【的最后一个元素】
```

大白话翻译这两个选择的用意：

| 指针 | 指向 | 为什么这么设计 |
|---|---|---|
| `front` | 第一个有效元素的**前一格**（一开始 -1） | 空的时候 `front`、`rear` 都停在 -1，判空天然就是 `rear == front`，不用特判 |
| `rear` | 最后一个有效元素**本身**（一开始 -1） | 入队只要 `rear++` 再写 `arr[rear]`，不用先算位置 |

所以记住一个约定：**`front` 那一格是空的（是"哨兵"），有效数据从 `front + 1` 开始，到 `rear` 结束。**

由此白嫖出两个公式：

```
是否空：rear == front
元素个数：rear - front
```

代码里 `showQueue` 的循环就是这么写的，这就是上面那句约定的直接落地：

```java
for (int i = front + 1; i <= rear; i++) { ... }
```

## 三、判空、判满，各一行

```java
public boolean isEmpty() { return rear == front; }        // 两个指针撞上 = 没数据
public boolean isFull()  { return rear == maxSize - 1; }  // rear 顶到数组最后一格 = 满
```

图示（`maxSize = 3`）：

```
① 空：两个指针都在 -1，撞上了
   索引    0     1     2
        ┌─────┬─────┬─────┐
        │     │     │     │
        └─────┴─────┴─────┘
     front ↑
      (-1)  rear ↑(-1)          rear == front  → isEmpty ✓

② 满：rear 顶到 maxSize-1
   索引    0     1     2
        ┌─────┬─────┬─────┐
        │  7  │  8  │  9  │
        └─────┴─────┴─────┘
     front ↑(-1)        ↑ rear = 2 = maxSize-1  → isFull ✓
```

## 四、入队 / 出队 到底动了什么

### 入队 `addQueue(n)`：先判满，再 `rear++`，再放值

```java
if (isFull()) { System.out.println("队列已满..."); return; }
rear++;
arr[rear] = n;
```

依次放入 1、2、3 的过程：

```
        rear 位置变化（front 全程不动，停在 -1）

放 1:   ┌───┬───┬───┐   放 2:  ┌───┬───┬───┐   放 3:  ┌───┬───┬───┐
        │ 1 │   │   │         │ 1 │ 2 │   │         │ 1 │ 2 │ 3 │
        └───┴───┴───┘         └───┴───┴───┘         └───┴───┴───┘
            ↑ rear=0                ↑   rear=1                ↑ rear=2 → 满了
```

### 出队 `getQueue()`：先判空，再 `front++`，再取值

```java
if (isEmpty()) { throw new RuntimeException("队列为空，不能取数据"); }
front++;
return arr[front];
```

注意一个**反直觉的点**：出队**并没有把 `arr[0]` 清成 0**。Java 里数组格子不能被"删掉"，出队只是把 `front` 往前挪一格，宣布「这一格我不认了」，数据还躺在那儿。

```
取出 1 之后（arr[0] 里那个 1 其实还在，只是已经"作废"）

   索引     0     1     2
          ┌─────┬─────┬─────┐
  arr  =  │ (1) │  2  │  3  │   有效区间 = front+1 .. rear
          └─────┴─────┴─────┘
               ↑           ↑
            front = 0     rear = 2      元素个数 = 2 - 0 = 2 ✓
```

## 五、这个实现的致命缺点：**只用得了一次**（学习重点，面试常问）

接着上图：现在 `front = 0`、`rear = 2`，队列里还有 2、3 两个数。此时你想再放一个 4 进去：

```
   索引     0     1     2
          ┌─────┬─────┬─────┐
          │(作废)│  2  │  3  │
          └─────┴─────┴─────┘
               ↑           ↑
            front=0     rear=2

  addQueue(4) → isFull() 判断 rear == maxSize-1 → 2 == 2 → true → "队列已满" ❗
```

明明 `arr[0]` 那个格子已经没人用了，却**放不进去**。这就是所谓的**「假满」**：数组有空位，但队列报满。

原因很直白：`front` 和 `rear` **只会往后走，从来不回头**。所以这个队列是**一次性**的 —— 从空装到满，再一路取到空，容量就永久报废了，只能重启程序。

```
空间利用情况（时间轴）：

 t0  [ 空 ][ 空 ][ 空 ]        可用 3
 t1  [ 1  ][ 空 ][ 空 ]  入队  可用 2
 t2  [ 1  ][ 2  ][ 3  ]  入队  可用 0（满）
 t3  [作废][ 2  ][ 3  ]  出队  看着有 1 个空位，实际不能用 ← 坑就在这
 t4  [作废][作废][ 3  ]  出队  同上
 t5  [作废][作废][作废]        容量彻底报废，再也塞不进任何东西
```

**解决办法：环形队列（循环队列）**，把数组头尾接起来看成一个圈，指针走到末尾就绕回 0（本项目已实现：[CircleArrayQueueDemo.java](./CircleArrayQueueDemo.java)，讲解见 [环形队列.md](./环形队列.md)）：

```
        rear = (rear + 1) % maxSize
        front = (front + 1) % maxSize

            ┌───┐   ┌───┐   ┌───┐
        ┌───┤ 0 ├───┤ 1 ├───┤ 2 ├───┐
        │   └───┘   └───┘   └───┘   │
        │                           │
    ┌───┴───┐                   ┌───┴───┐
    │   7   │                   │   3   │
    └───┬───┘                   └───┬───┘
        │   ┌───┐   ┌───┐   ┌───┐   │
        └───┤ 6 ├───┤ 5 ├───┤ 4 ├───┘
            └───┘   └───┘   └───┘

   下标 7 再往后一步，绕回 0 —— 空出来的"作废格"就能被重新利用

   判空：front == rear
   判满：(rear + 1) % maxSize == front   （故意留一个格子不装数据，用来区分"空"和"满"这两种 front==rear 的情况）
```

这就是为什么 Java 标准库的 `ArrayDeque`、`LinkedQueue` 内部要绕圈。你现在写的这个版本，价值在于**把指针的每一步走清楚**，理解了它，循环队列的 `%` 只是水到渠成的补丁。

## 六、异常处理：为什么出队「抛异常」，入队「打印一行」？

这是这段代码里最值得琢磨的设计选择，两个方法面对的都是「操作做不了」，但方式不同：

| 方法 | 有返回值吗 | 失败时怎么办 | 为什么 |
|---|---|---|---|
| `addQueue` | `void`（没返回值） | `System.out.println` + `return` | 没什么要交回给调用方的，打印一句就完事 |
| `getQueue` | `int`（必须返回一个数） | `throw new RuntimeException(...)` | 队列空着，**返回哪个数都是错的**（返回 0？可 0 可能是真实数据），只能用异常说「我没法给你结果」 |
| `headQueue` | `int` | 同上 | 同上 |

### 传递链路：方法里抛，main 里接

```
main (case "g")                      ArrayQueue.getQueue()
────────────────                    ────────────────────
try {                               if (isEmpty())
    int res = arrayQueue        ┌───│     throw new RuntimeException(
        .getQueue();  ← 调用 ────┘   │         "队列为空，不能取数据")
    System.out.printf(...)          └─── 方法立刻中断，front++ 根本不执行
} catch (Exception e)  ←── 异常沿调用栈往上冒，冒到这里被抓住
    System.out.println(e.getMessage());   取出一开始传进去的那句话
```

三个要点：

1. **`throw` 一执行，方法后面的代码全部作废**（`front++` 和 `return` 都别想跑）。
2. `RuntimeException` 属于**非受检异常**，所以方法签名上**不用**写 `throws`，编译器不强制你处理。换成 `IOException` 那种受检异常就必须写 `throws` 或者就地 catch。
3. `catch (Exception e)` 能接住它，是因为继承关系：`RuntimeException` → `Exception` → `Throwable`。

### ⚠️ 但 `Exception` **不是**「最大的类」，别理解反了

真正的根类是 `Throwable`，它下面分**两支**：

```
Throwable
├── Error                         ← catch(Exception) 抓不到！
│     StackOverflowError, OutOfMemoryError（一般也不该去抓）
└── Exception                     ← catch(Exception) 能抓住这一整支
      ├── 受检异常  IOException / SQLException ...
      └── RuntimeException  NullPointer / InputMismatch ...
```

所以 `catch (Exception e)` 的准确说法是「能兜住所有 **Exception 家族**」，而不是「所有异常」。想兜住一切得写 `catch (Throwable t)`（实际项目里基本不这么干）。

### ⚠️ 更要命的：try 只护住它包起来的那几行

这段代码把 try 写在 `case 'g'`、`case 'h'` 里面（细粒度），意味着**没被包住的调用一旦炸，程序直接退出**。最典型的一处：

```java
case 'a':
    System.out.println("请输入一个数字");
    int value = scanner.nextInt();   // ← 这里没有 try！
    arrayQueue.addQueue(value);
```

你在菜单输入 `abc`，`scanner.nextInt()` 会抛 `InputMismatchException`（它同样是 RuntimeException），但它**不在任何 try 里**，于是直接冒穿 main：打印一大坨堆栈、程序结束 —— 而不是你以为的「友好提示一下继续」。想避免，就在这一层套 try，或者干脆把整个 while 包起来。

顺带一提：`switch` 没写 `default` 分支，所以输入 `x` 之类的字符会被**静默忽略**，直接重新打菜单。

## 七、性能账本

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `addQueue` | O(1) | 就是 `rear++` + 一次赋值 |
| `getQueue` | O(1) | 就是 `front++` + 一次取值 |
| `headQueue` | O(1) | 直接读 `arr[front+1]` |
| `showQueue` | O(n) | 要遍历一遍 |
| 空间 | O(maxSize) | 但**实际可用容量会随出队浪费**（第五节那个坑） |

队列的全部魅力就在「入队出队都是 O(1)」，这也是它比数组头部插入（要整体后移，O(n)）强的地方。

## 八、动手验证（PowerShell 用 `;` 分隔，不能用 `&&`）

```powershell
javac -encoding UTF-8 -d out src\com\ittxf\queue\ArrayQueueDemo.java
java -cp out com.ittxf.queue.ArrayQueueDemo
```

建议按这个剧本走一遍，亲眼确认每个结论：

| 步骤 | 输入 | 预期现象 | 验证的知识点 |
|---|---|---|---|
| 1 | `g` | 打印 `队列为空，不能取数据`，程序**不崩** | throw → catch 链路 |
| 2 | `h` | 打印 `队列为空，没有数据` | 同上 |
| 3 | `a` `10` `a` `20` `a` `30` | 连续入队成功 | `rear` 逐步后移 |
| 4 | `a` `40` | `队列已满` | `rear == maxSize - 1` |
| 5 | `s` | 打印 10 / 20 / 30 三行 | `front+1 .. rear` 区间 |
| 6 | `g`（取走 10） | 取出 10 | `front++`，数据没真删 |
| 7 | `a` `40` | **又报「队列已满」** | ⭐ 第五节的「假满」，复现成功 |
| 8 | `g` `g` | 依次取出 20、30 | 空判 `rear == front` 生效 |
| 9 | `a` `abc` | ⭐ 一大坨堆栈，程序**崩掉** | try 没包住 `nextInt()` |

第 7 步和第 9 步是这段代码真正的"知识点所在"，跑一遍比看十遍都管用。

## 九、一句话记住队列

> **尾巴进、头出；`front` 指着"头前面那一格"当哨兵，`rear` 指着"尾巴那一格"；两个指针只会往后走，所以数组版用一次就废 —— 这就是循环队列存在的理由；出队必须给个数却给不出来时，用 `throw`，让调用方 `catch`。**

## 十、往下学什么

1. **环形队列** ✅ 已完成：见 [环形队列.md](./环形队列.md) 和 [CircleArrayQueueDemo.java](./CircleArrayQueueDemo.java)。把 `% maxSize` 加进 `addQueue`/`getQueue` 后，上面剧本第 7 步那句「队列已满」会变成成功入队（我两个程序都实际跑过对照，差异就在那一步）。代价是为了区分空/满要牺牲一个格子：传 4 只能存 3 个。
2. **数组队列 vs 链表队列**：链表版不存在容量问题，也不用绕圈 —— 节点与指针的写法见 [单链表.md](../linkedlist/%E5%8D%95%E9%93%BE%E8%A1%A8.md)，它的 `add` 尾插正好当入队、`delete` 搭桥摘牌正好当头节点出队。
3. **JDK 里的现成货**：`ArrayDeque`（循环数组）、`LinkedList`（链表）、`LinkedBlockingQueue`（多线程，`offer/poll` 有"不阻塞"变体）。看看它们的 `head/tail` 命名和你写的 `front/rear` 怎么对上。

# 双向链表

> 对应程序：[DoubleLinkedListDemo.java](./DoubleLinkedListDemo.java)
> 它是 [单链表.md](./%E5%8D%95%E9%93%BE%E8%A1%A8.md) 的直接升级：节点多背一根 `pre` 线，于是"删除"这件事从"必须找前驱"变成"自己摘自己"。
> ⚠️ 本篇有一个**实测确认的真 bug**（第四节），建议先看完那一节再动代码。

---

## 一、多出来的那根线，到底改变了什么

单链表的节点只知道"下一个是谁"，不知道"我是谁的下一个"：

```
   单链表：一条道走到黑，回头路没有
   ┌─────┐     ┌─────┐     ┌─────┐
   │  1  ├────►│  2  ├────►│  3  ├────► null
   └─────┘     └─────┘     └─────┘
   想知道 2 的上面是谁？只能从 head 重新走一遍

   双向链表：每个节点都记着"我从哪儿来"
   ┌─────┐      ┌─────┐      ┌─────┐
   │  1  │ ◄───►│  2  │ ◄───►│  3  │ ◄───► null(head)
   └─────┘      └─────┘      └─────┘
     next 走右边，pre 走左边，两根线必须成对出现
```

对应的节点定义只多了一行：

```java
class DHeroNode {
    public int no;
    public String name;
    public String nickname;
    public DHeroNode next;   // 指向后一个
    public DHeroNode pre;    // ★ 指向前一个 —— 全文就多了这一个字段
}
```

**一句话概括收益：凡是"需要知道前驱"的操作，从此不用从头遍历了。** 单链表删除必须拖着一个"前一个节点"的指针走（第四节那张表里的痛点），双向链表直接 `temp.pre` 拿到。

## 二、哨兵 head 在双向链表里的新身份

`DoubleLinkedList` 里仍然是那个不动的空壳：

```java
private final DHeroNode head = new DHeroNode(0, "", "");
```

但它在**两个方向**上的含义不一样，这点必须先钉死：

```
   head ⇄ 1 ⇄ 2 ⇄ 3 ⇄ null
     ↑
   head.next = 第一个数据节点   （和单链表一样）
   head.pre  = null            ★ 没人给哨兵连 pre，它就是 null
   第一个数据节点的 pre = head  （不是 null！）
```

为什么 `第一个节点的 pre == head` 而不是 null 很重要？第五节实测会看到：**删第一个数据节点时执行的是 `temp.pre.next = ...`，靠的就是 `temp.pre` 一定不是 null**。哨兵在这里第二次兑现了它的价值（第一次是让删除不用特判头节点）。

反过来，`tail.next == null`（本代码没有 tail 指针），所以 `temp.next.pre = ...` 这句**必须判空** —— 这两处不对称，是双向链表最容易写错的地方。

## 三、五个方法与单链表逐条对照

### 1. `add` 尾插：从 1 句变 2 句

```java
temp.next = heroNode;    // 前面的尾巴指向新节点
heroNode.pre = temp;     // ★ 新节点回指前面的尾巴
```

```
   ① temp.next = heroNode          ② heroNode.pre = temp
   temp ────────► heroNode         temp ◄──────── heroNode
   （只做完 ① 的话，新节点不知道自己前面是谁，反向链就断了）
```

### 2. `update`：**和单链表一字不差**

这是个很好的对照点：`update` 只改 `name`/`nickname`，**一根线都不碰**，所以有没有 `pre` 完全无所谓。

**推论**：改一个节点的"数据"永远比改它的"位置"简单。凡是只读/写数据字段的操作，链表结构升级对它无影响。

### 3. `list`：仍然只走 `next`

```java
DHeroNode temp = head.next;
while (true) { if (temp == null) break; System.out.println(temp); temp = temp.next; }
```

从单链表复制过来，一行没改。**这也是第四节那个 bug 藏了这么久的原因**——`list()` 只验了 `next` 一个方向，`pre` 断了它看不见。

### 4. `addByOrder`：3 句赋值，但**缺了致命的第 4 句**

```java
heroNode.next = temp.next;   // ① 新节点接住后面的链（先接后断，和单链表同一条铁律）
temp.next = heroNode;        // ② 前驱指向新节点
heroNode.pre = temp;         // ③ 新节点回指前驱
                             // ✗ 缺：④ 后继回指新节点 —— 就是这里出的事
```

第四句应该是：

```java
if (heroNode.next != null) heroNode.next.pre = heroNode;
```

后果见第四节实测。插入到**末尾**时 `temp.next` 本来就是 null，所以不需要第 ④ 句（`add` 方法因此没有 bug）；**只有插到中间**才暴露 —— 而 `addByOrder` 干的正是"插到中间"。

### 5. `delete`：这是双向链表真正的收获

```java
DHeroNode temp = head.next;        // ★ 直接找目标节点本身，不用拖前驱
if (temp.no == no) { flag = true; break; }
...
temp.pre.next = temp.next;                    // ④ 前驱的 next 迈过 temp
if (temp.next != null) temp.next.pre = temp.pre;   // ⑤ 后继的 pre 迈过 temp（尾节点要判空）
```

```
   删除 2 号节点：

   1 ⇄ [2] ⇄ 3        ④ 1.next = 3        1 ⇄ ╳   ═══► 3        ⑤ 3.pre = 1
   （temp 就停在 2 上）                     1 ═══════════════► 3   （2 成为孤儿，GC 收走）

   单链表要做到同样的事，temp 必须停在 1 上（比 temp.next.no），
   而双向链表 temp 可以直接停在 2 上（比 temp.no）—— 一根 pre 换来的自由
```

## 四、⚠️ 实测确认的 bug：插到中间时，后继的 `pre` 没有回连

我写了个临时探针（跑完已删），插入顺序**完全照搬你 `main` 里的 1、4、2、3**，然后把 `next` 链和 `pre` 链各走一遍：

```
[原版] 插入 1,4,2,3 后：
  正向 next 链：1 -> 2 -> 3 -> 4 -> (null)        ← list() 只看这个，一切正常 ✅
  反向 pre  链：4 -> 1 -> head                    ← ❌ 应该是 4 -> 3 -> 2 -> 1 -> head
  每个节点的 pre 指向：
    1.pre = head    ✅
    2.pre = 1       ✅
    3.pre = 2       ✅
    4.pre = 1       ❌ 应为 3
```

**根因**：`4` 最早作为尾巴插入时 `4.pre = 1` 是对的；后来 `2`、`3` 先后插到它**前面**，可 `addByOrder` 只连了新节点自己的两根线，从没更新过**后继**（4）的 `pre`，于是 `4.pre` 一直停在 `1`。

### 它什么时候炸？

`delete` 依赖 `pre`，所以 `pre` 一断，删除就会删错东西：

```
[原版] 另建同样的四条链，直接 delete(4)（删最后一个）：
  正向 next 链：1 -> (null)
  ↑ 本应剩 1、2、3，结果 2 和 3 被整体甩丢！
```

因为 `temp(4).pre` 是 `1`，于是执行 `temp.pre.next = temp.next` 就等于 `1.next = null` —— 把 2、3 整段从链上摘掉了。

### 为什么你 `main` 现在的输出看起来是对的？

```
[原版] delete(3)（main 里现在就是这个）：
  正向 next 链：1 -> 2 -> 4 -> (null)     ✅ 正确
  反向 pre  链：4 -> 2 -> 1 -> head       ✅ 顺带被修好了
```

纯属**歪打正着**：`3.pre = 2` 恰好是对的（3 是最后一次插入的，它的 pre 被当场连对了），而删 3 时执行了 `temp.next.pre = temp.pre`，也就是 `4.pre = 2` —— 顺手把那个一直错的 `4.pre` 给改对了。**删除动作恰好充当了一次修复**，所以 bug 被掩盖了。

换个删除目标（先删 4、或只删 4）立刻暴露。**这类"靠顺序掩盖的 bug"是最危险的一类**：现有测试全绿，改一行数据就崩。

### 一行修复（我实测过，只写进笔记，没改你的代码）

```java
// addByOrder 末尾追加这一句
if (heroNode.next != null) heroNode.next.pre = heroNode;
```

修复版实测（同样的插入顺序）：

```
[修复版] 正向 next 链：1 -> 2 -> 3 -> 4 -> (null)
[修复版] 反向 pre  链：4 -> 3 -> 2 -> 1 -> head      ✅ 每个 pre 都对了
         删尾节点 4：正向 1 -> 2 -> 3 ✅   删首节点 1：正向 2 -> 3 ✅ 反向 3 -> 2 -> head ✅
```

### 可复用的教训

**双向链表必须"双向各遍历一次"才算验证完成。** 只用 `list()`（走 `next`）测试，等于只验了一半的指针；任何一条 `pre` 接错都不会有提示。写一个 `listReverse()` 从尾巴走 `pre` 回来，成本 5 行，能抓出这类隐蔽 bug —— 建议当作业补上（第十二节）。

## 五、`delete` 里那两句的顺序与两个边界（都实测过）

```java
temp.pre.next = temp.next;
if (temp.next != null) temp.next.pre = temp.pre;
```

**两句的顺序可以互换**（都不动 `temp.pre`/`temp.next` 本身，读的是同一份旧值），但**都不能省**。真正不能碰的是 `temp.pre` 自己 —— 一旦写了 `temp.pre = null`，后面那句就找不着前驱了。

两个边界，探针实测的异常类型都是 `NullPointerException`：

```
[反例1] 删尾节点时去掉 if (temp.next != null) 保护：
  抛 java.lang.NullPointerException      ← 因为 temp.next 是 null，null.pre 赋值直接炸
[反例2] 没有哨兵、删第一个节点时 temp.pre 为 null：
  抛 java.lang.NullPointerException      ← 哨兵让 temp.pre 永远不为 null，这句才敢裸写
```

对照着记，**这两处不对称是双向链表最典型的写错点**：

| 边界 | 靠什么安全 | 单链表有这个问题吗 |
|---|---|---|
| 删**第一个**数据节点 | 哨兵保证 `temp.pre != null`，所以第一句可以裸写 | 没有（本来就从头找前驱） |
| 删**最后**一个节点 | 必须 `if (temp.next != null)` 判空 | 没有（`temp.next = temp.next.next` 赋 null 是合法的） |

也就是说：**升级到双向链表，删除代码少了"找前驱"的遍历，却多了"尾节点判空"的特判** —— 有得必有失，别以为纯赚。

## 六、单链表 vs 双向链表：全维度对照

| 维度 | 单链表（`SingleLinkedListDemo`） | 双向链表（本代码 `DoubleLinkedListDemo`） |
|---|---|---|
| 节点字段 | `no/name/nickname/next` | 多一个 `pre` |
| 每节点内存 | 1 个引用 | 2 个引用（64 位 JVM 各约 4~8 字节） |
| 尾插 `add` | 1 句赋值 | 2 句 |
| 有序插入 `addByOrder` | 2 句 | 3 句（**应 4 句，本代码缺 1**） |
| `update` | 完全相同 | 完全相同（不碰线） |
| 删除时 `temp` 停在 | **前驱**（比 `temp.next.no`） | **目标本身**（比 `temp.no`） |
| 删除赋值语句 | `temp.next = temp.next.next`（1 句） | `temp.pre.next=...` + `temp.next.pre=...`（2 句 + 1 判空） |
| 反向遍历 | ❌ 做不到，只能借栈（见 [栈.md](./%E6%A0%88.md)） | ✅ 顺 `pre` 走即可 |
| 已知节点指针时删除 | O(n)（要找前驱） | **O(1)** |
| 按编号查找 | O(n) | O(n) —— **别误以为双向就快了** |
| 出错面 | 少一根线，简单 | 两根线必须成对维护，漏一句就"半瞎" |
| JDK / 工业界谁在用 | 简单队列、`ChainMap` 之类 | `LinkedList`、`HashMap` 的链表/红黑树桶、LRU 缓存、`TreeMap` 节点 |

关于"查找还是 O(n)"这点，值得单独钉一下：`delete` 方法里从 `head.next` 开始的 `while` 循环**一个都没少**，`pre` 在这一步帮不上忙（我们只有编号，没有节点引用）。`pre` 省的是"找前驱"的那一段，不是"找节点"的那一段。**双向链表的加速只在"我手里已经握着这个节点"时才成立** —— 这也是 `HashMap` 用双向链表存桶的原因：它拿得到节点本身。

## 七、复杂度总账

| 操作 | 时间 | 说明 |
|---|---|---|
| `add` 尾插 | O(n) | 找尾巴；存个 `tail` 指针就能变 O(1) |
| `addByOrder` | O(n) | 遍历定位 |
| `update` / `delete` / `list` | O(n) | 按编号线性找 |
| 已知节点引用时插入/删除 | **O(1)** | 双向链表的主场（单链表删除要 O(n) 找前驱） |
| 空间 | O(n) | 每节点多一根 `pre` |

## 八、这份代码里其他几处可商榷的地方

1. **`main` 里的变量名叫 `singleLinkedList`，类型却是 `DoubleLinkedList`。** 从单链表版整段复制时忘了改名，读代码时会反复误判"这到底是哪条链"。改成 `doubleLinkedList` 或 `list`。
2. **`import java.util.Stack;` 未使用。** 也是复制残留（单链表版的 `reversePrint` 才用栈）。IDEA 会灰字提示，删掉即可。
3. **`delete` 里那句注释是错的**：`DHeroNode temp = head.next; // 用来分别是否停在待删除节点的前一个节点` —— 双向链表的 temp 恰恰停在**待删除节点本身**（这正是升级的意义），注释是从单链表版抄来的。此外"分别"应为"判断"。
4. **类注释 `// 定义HeroNode，每个 HeroNode 对象就是一个节点`** 写在 `DHeroNode` 上方，名字对不上。
5. **只实现了 5 个基本操作**：反转、逆序打印、合并都没有。有意思的是——**双向链表做"逆序打印"不再需要栈**，从尾巴顺着 `pre` 走就行（但当前没有 `tail` 指针，找尾巴要遍历一次）。
6. 与单链表版**重复度很高**：两套 `add/update/list` 逻辑几乎一样。真实项目里会抽公共接口（如 `List`/`Deque`），练习阶段先并存没问题，但要知道这是重复代码。

## 十、一句话记住双向链表

> **每个节点多背一根 `pre`，换来"删除不用找前驱"的自由：`temp` 直接停在目标上，两句 `temp.pre.next = temp.next` 与 `temp.next.pre = temp.pre` 把自己摘出去；代价是尾节点要判空（`temp.next` 可能是 null），而首节点不用（哨兵保证 `temp.pre` 不是 null）；插入必须四根线一次连齐 —— 本代码的 `addByOrder` 只连了三根，后继的 `pre` 成了孤儿，`list()` 因为只走 `next` 所以看不见，一旦删到尾节点就把中间整段甩丢。**

## 十一、往下学什么

1. **补上第四节那一行修复**，并把 `main` 的 `delete(3)` 改成 `delete(4)` 当作回归测试 —— 改完两次的输出都会是对的。
2. **加一个 `tail` 指针**：`add` 立刻变 O(1)，而且反向遍历不用再找尾巴。注意插入/删除时要同步维护 `tail`，这是"冗余字段"的经典代价。
3. **写一个 `listReverse()`**：从尾巴顺 `pre` 打印。三行代码，却能把 `pre` 链的正确性暴露出来（第四节那个 bug 如果有这个函数，第一天就会被抓到）。
4. **双向链表反转**：交换每个节点的 `pre`/`next`，最后把头尾对调；比单链表反转简单，但要注意哨兵别被换进去。
5. **约瑟夫环** ✅ 已有单向版：见 [约瑟夫环.md](./%E7%BA%A6%E7%91%9F%E5%A4%AB%E7%8E%AF.md) 与 [Josepfu.java](./Josepfu.java) 里的 `CircleSingleLinkedList`（尾节点 `next` 指回 `first` 成环，`first` + `helper` 双指针报数出圈）。把它升级成**循环双向链表**是顺势的练习：多出 `pre` 可以倒向报数，但出圈时必须同时缝好 `pre` 和 `next` 两侧 —— 正好复用本篇第四节“少连一根线”的教训。
6. **回看 [单链表.md](./%E5%8D%95%E9%93%BE%E8%A1%A8.md) 与 [栈.md](./%E6%A0%88.md)**：同一件"逆序打印"的事，单链表借栈（O(n) 空间）、双向链表用 `pre`（O(1) 空间）—— 数据结构多一个字段，省掉的就是整一个辅助结构，这笔账最值得体感一次。

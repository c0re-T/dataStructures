## 一、栈就是一摞盘子：后进先出（LIFO）

一句话：**只能从同一头进出，最后放上去的最先拿。**

```
   压栈(push)                                  弹栈(pop)
       ↓                                          ↑
   ┌───────┐   ← 栈顶(top)                    ┌───────┐
   │ jerry │                                  │ jerry │  ← 先出来的是它
   ├───────┤                                  ├───────┤
   │  tom  │                                  │  tom  │
   ├───────┤                                  ├───────┤
   │ jack  │   ← 栈底(bottom)                 │ jack  │
   └───────┘                                  └───────┘
      空 = 栈里没有东西

   放盘子的顺序 jack → tom → jerry，拿走时只能是 jerry → tom → jack
```

跟队列（[队列.md](../queue/队列.md)）正好是一对反义词，这俩最容易混，一次记死：

| | 栈 Stack | 队列 Queue |
|---|---|---|
| 规矩 | **LIFO** 后进先出 | **FIFO** 先进先出 |
| 生活类比 | 一摞盘子、弹夹、回溯走过的路 | 排队买票、取号、水管 |
| 入口/出口 | 同一个口（栈顶） | 尾进头出（两个口） |
| 典型用途 | 撤销、函数调用、括号匹配、DFS | 任务排队、消息队列、BFS |

**判断该用哪个的口诀：需要"回到最近的一次"就用栈；需要"别插队、按顺序来"就用队列。**

## 二、TestStack 逐行：只有 3 件事

```java
Stack<String> stack = new Stack<>();      // 建一个空栈
stack.push("jack");                       // 入栈
stack.push("tom");
stack.push("jerry");
System.out.println(stack);                // [jack, tom, jerry]  ← 打印顺序是 底 → 顶
while (!stack.isEmpty()) {                // 栈不空就一直弹
    System.out.println(stack.pop());      // 弹栈：jerry → tom → jack
}
```

> 这份代码早期用的是 `stack.add(...)`，现在已经统一改成 `stack.push(...)`。两者行为完全等价（原因见第三节），但 `push` 一看就知道是栈操作，可读性更好。

实测输出（原样跑出来的）：

```
[jack, tom, jerry]
jerry
tom
jack
```

三个必须建立的认知：

1. **`toString()` 打印的是"从栈底到栈顶"**，所以 `[jack, tom, jerry]` 里 **jerry 才是栈顶**。别把左边当成顶。
2. **`pop()` 一次拿一个，顺序与入栈完全相反** —— 这就是 LIFO 的全部内容。
3. **`while (!stack.isEmpty())` 是安全写法**：先判空再弹，永远不会碰空栈异常（第五节会说要是不判会怎样）。

## 三、`add` 和 `push` 为什么可以混用：栈顶就是尾部

入栈用 `push` 还是用 `add`，效果完全一样（本项目早期版本用的就是 `add`，后来统一改成了 `push`）。原因藏在继承关系里：

```
   java.util.Stack  extends  java.util.Vector  extends  AbstractList
        （栈）              （可增长数组）         （List 契约）

   Stack 的"栈顶"= Vector 数组的【尾部】，所以：
   push(x)  ≈  add(x)  ≈  addElement(x)     —— 都是往尾巴后面接一个
   pop()    ≈  remove(size-1)               —— 都是把尾巴那个摘下来
```

```
   内存里其实还是一个数组，只是"只允许动尾巴"：
   ┌──────┬──────┬──────┬──────┐
   │jack  │ tom  │jerry │(空闲)│            下标 0 ────────────→ size-1
   └──────┴──────┴──────┴──────┘                              ↑
    栈底                                              栈顶在这里，进出都只碰这一格
```

探针实测确认两者等价（`add` 两次 + `push` 一次混着用）：

```
add/push 混用，toString=[jack, tom, jerry]   peek=jerry     ← 谁最后进来谁是顶，与方法名无关
```

**风格建议**：栈的语义要用 `push`/`pop`/`peek` 这套动词写，读代码的人一眼就知道"这是个栈"；`add` 是 List 的动词，会让人误以为可以随意插。功能相同，可读性不同。

## 四、API 速查表

| 方法 | 干什么 | 空栈/找不到时 | 实测 |
|---|---|---|---|
| `push(V)` | 入栈，返回入栈的元素 | 不会失败（容量自动增长） | — |
| `pop()` | 弹出栈顶并返回 | **`EmptyStackException`** | ✅ 已实测 |
| `peek()` | 只看栈顶**不弹出** | **`EmptyStackException`** | ✅ 已实测 |
| `empty()` / `isEmpty()` | 判空，两个都能用（前者是 Stack 的古老名字） | — | ✅ 都返回 true |
| `size()` | 元素个数 | 空栈返回 0 | — |
| `search(Object)` | 找元素离栈顶多远，**从 1 开始数**：栈顶=1，栈底=n | 找不到返回 **-1**（不是 0！） | ✅ `search(jerry)=1`、`search(jack)=3`、`search(nobody)=-1` |
| `add` / `add(i,x)` / `remove(Object)` | 继承自 Vector 的 List 方法 | — | ⚠️ 见第五节 |

`search` 那行值得多盯一眼，是个高频错点：

```
   [jack, tom, jerry]        jerry → 1（栈顶）    tom → 2    jack → 3（栈底）
   找不到 → -1，所以判断写法必须是 if (stack.search(x) != -1)，不能写成 if (... > 0) 之外的怪写法
```

## 五、⚠️ JDK `Stack` 最大的问题：它是个"漏"的抽象

栈的全部价值在于**只允许动栈顶**这一条约束。可 `Stack` 是 `Vector` 的子类，于是 List 的那套方法原封不动全继承过来了，随便一调就能把 LIFO 打穿。探针实测：

```java
stack.add(0, "插到底部");     // 从栈底插！
stack.remove("tom");          // 直接掏走中间那个
```

```
   原栈（底→顶）：[jack, tom, jerry]
   add(0, x) 后：  [插到底部, jack, tom, jerry]   pop() 拿到的还是 jerry，但底下已经被塞乱了
   remove("tom")： [插到底部, jack]               ← tom 被从中间抽走，这根本不再是栈操作
```

这不是我用法刁钻，而是 JDK 自己的历史包袱：**`Stack` 用"继承"复用了 `Vector`，把实现细节暴露成了 API**（《Effective Java》第 18 条点名的反面教材：继承违背了里氏替换 —— 栈不该有"在中间插入"的能力）。

### 更推荐的写法：`ArrayDeque`

```java
Deque<String> stack = new ArrayDeque<>();   // 面向 Deque 接口，没有 List 后门
stack.push("jack");                          // addFirst 的封装，栈顶在头部
System.out.println(stack.pop());             // removeFirst
System.out.println(stack.peek());            // getFirst，空栈时返回 null
```

| 对比项 | `java.util.Stack` | `ArrayDeque` 当栈用 |
|---|---|---|
| 有没有"中间插入"后门 | ⚠️ 有（继承 Vector） | ✅ 没有（只给双端队列操作） |
| 同步 | 每个方法都 `synchronized`，单线程白白付出代价 | 不同步，更快 |
| 空栈 `pop()` | `EmptyStackException` | `NoSuchElementException`（另有 `poll()`/`peek()` 返回 `null` 的温和版本） |
| 能否存 `null` | 能 | ❌ 不能（因为要用 null 表达"空"） |
| 底层 | 可增长数组 | 循环数组（和 [环形队列.md](../queue/环形队列.md) 一家子） |

两种空栈异常类型**不一样**这点我是实测过的，写 catch 时别抄错：

```
空栈 pop -> java.util.EmptyStackException            （Stack）
ArrayDeque 空栈 pop -> java.util.NoSuchElementException （ArrayDeque，poll 则返回 null）
```

**结论**：练习/面试手写栈无所谓；生产代码里 JDK 官方文档自己就写着"栈应该用 `ArrayDeque` 或 `Deque` 实现"。本课程用 `Stack` 只是为了演示概念。

## 六、三个高频坑（都实测过）

**坑 1：不判空就 `pop()` / `peek()`**

```java
stack.pop();   // 空栈 → java.util.EmptyStackException（RuntimeException 家族，编译器不会提醒你）
```

安全写法三选一：`while (!stack.isEmpty())`（本代码用的）、先 `if (stack.empty()) return;`、或改用小写的 `poll()`（ArrayDeque，空时返回 `null` 不抛）。

**坑 2：以为 `toString` 左边是栈顶。** 实际是**栈底在左**，`[jack, tom, jerry]` 的顶是 jerry。for-each 遍历也是底→顶（实测 `1 2 3`），**不能用遍历代替弹栈**——遍历是正序，弹栈是倒序。

**坑 3：把 `search` 的返回值当"下标"。** 它是"距离栈顶第几层"，从 1 起算，找不到是 **-1**。而栈的底层数组下标是从 0 起算的"距栈底"，两套坐标方向相反，别混。

## 七、栈为什么和链表放在一起讲

[单链表.md](单链表.md) 第八节的 `reversePrint` 就是本篇的直接应用：单链表只能从头往后走（`next` 是单向的），想倒着看，就把节点全压进栈，再逐个弹出 —— **借栈的 LIFO 换到"逆序"**。

```
   链表 1 → 3 → 4                 压栈（底→顶）              弹出顺序
   ┌───┐ ┌───┐ ┌───┐            ┌─────┬─────┬─────┐        4 → 3 → 1
   │ 1 ├►│ 3 ├►│ 4 ├► null  ──► │  1  │  3  │  4  │  ──►
   └───┘ └───┘ └───┘            └─────┴─────┴─────┘
      只能往右走                 栈顶在右（后进）      出来就是反的
```

代价对比（也是笔记里那张表的核心）：栈 O(n) 空间但**不改原链表**；反转链表 O(1) 空间却**会改指针**。"要不要保留原数据"决定了选哪个。

顺着这条线再看一层：**函数调用栈**就是操作系统给你的一串栈帧 —— 递归之所以能"回到上一层"，靠的就是这个栈。链表递归反转、深度优先搜索，本质都是"把状态压栈"。所以栈不是孤立的一个数据结构，它是所有"回溯/撤销/嵌套"操作的地基。

## 八、复杂度总账

| 操作 | 时间 | 说明 |
|---|---|---|
| `push` | 均摊 **O(1)** | 尾部接一个；容量不够时像数组一样扩容（所以是"均摊"） |
| `pop` / `peek` | **O(1)** | 只碰尾巴那一格 |
| `empty` / `isEmpty` / `size` | **O(1)** | — |
| `search` | **O(n)** | 从顶往下线性找 |
| `add(0,x)` / `remove(Object)` | O(n) | ⚠️ 有这能力本身就是设计缺陷，别用 |
| 空间 | **O(n)** | 存 n 个元素，扩容时最多多一倍 |

一句话：**栈的全部优势就是"进出都只看一张牌"，一旦你开始用它中间插入或查找，优势立刻归零。**

## 十、栈在真实世界干什么

代码里只是"存名字再弹出来"，实际应用多到数不完：

- **撤销 / Ctrl+Z**、编辑器重做栈、浏览器"后退"按钮 —— 每个都是"把历史压栈，弹栈即回退"。
- **函数调用栈**：方法嵌套调用、递归、异常栈 `stackTrace`（`at xxx.java:111` 那一串就是栈）。
- **括号匹配**：遇到左括号入栈，遇到右括号弹栈比对 —— 编译器检查语法的第一步。
- **表达式求值 / 逆波兰**：`3 4 + 5 *` 这种后缀式，只要一个栈就能算完（编译原理、计算器、JVM 字节码执行引擎）。
- **深度优先搜索（DFS）**：迷宫、图的遍历、文件目录递归 —— 队列是 BFS，栈是 DFS。
- **单调栈**：求"下一个更大元素"、柱状图最大矩形、每日温度（LeetCode 739/84）—— 栈的进阶形态。
- **虚拟机与表达式引擎**：JVM 的操作数栈、Lua/Forth 整门语言以栈为计算核心。

## 十一、一句话记住栈

> **栈就是只准动栈顶的数组：`push`/`pop`/`peek` 全是 O(1)，`toString` 打印是"栈底在左、栈顶在右"，所以 `[jack, tom, jerry]` 里 jerry 才是顶；JDK 的 `Stack` 继承 `Vector`，把 `add(0,x)`、`remove(Object)` 这些"中间操作"全暴露了出来，LIFO 约束形同虚设，生产环境建议改用 `ArrayDeque`；空栈 `pop` 抛 `EmptyStackException`，`search` 从 1 起算、找不到返回 -1。**

### 附：四种栈实现全景对照

| | `java.util.Stack` | `ArrayDeque` | `ArrayStack`（自造） | `LinkedStack`（自造） |
|---|---|---|---|---|
| 底层 | 可增长数组（继承 Vector） | 循环数组 | 定长 `int[]` + `top` 下标 | 节点 + `top` 引用 |
| 栈顶位置 | 数组尾部 | 头部（`push` = `addFirst`） | 下标 `top` 那一格 | 链表头节点 |
| 容量 | 自动扩容 | 自动扩容 | **写死 `maxSize`**，满了只能提示 | 无上限（直到 OOM） |
| 有没有"中间插入"后门 | ⚠️ 有 | ✅ 无 | ✅ 无（字段私有） | ✅ 无（字段私有） |
| `size()` | O(1) | O(1) | O(1)（`top + 1`） | O(1)（靠 `count`）／不存则 O(n) |
| 同步开销 | 每个方法 `synchronized` | 无 | 无 | 无 |
| 空栈 `pop` | `EmptyStackException` | `NoSuchElementException` | `RuntimeException`（自定义文案） | `RuntimeException`（自定义文案） |

选哪个：学习阶段自己造（数组版、链栈版各写一遍，把 `top` 的两种语义装进脑子）；生产代码用 `ArrayDeque`；`java.util.Stack` 只当历史案例认识。

另：数组版 `ArrayStackDemo` 的笔记也已成篇 —— [数组栈.md](../stack/%E6%95%B0%E7%BB%84%E6%A0%88.md)（`top` 语义、前后置自增的坑、以及为什么数组栈不会"假满"）。

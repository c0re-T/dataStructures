# 约瑟夫环（环形单向链表）

> 对应程序：[Josepfu.java](./Josepfu.java)
> 数据结构其实是**环形单向链表**（循环链表），约瑟夫只是它最著名的用途。
> 前置阅读：[单链表.md](./%E5%8D%95%E9%93%BE%E8%A1%A8.md) 第四节"搭桥摘牌" —— 本篇出圈那一刀用的就是它。

---

## 一、问题是什么，为什么要"环"

> n 个人围坐一圈，从第 `startNo` 个人开始报数，数到 `countNum` 的人出圈，然后从他下一个人重新报 1，问出圈顺序、最后剩下谁。

用普通单链表做这件事，最大的麻烦是**走到尾巴就断了**：报数要绕回去继续，`next == null` 之后无处可去。解决办法朴素到极点——**让最后一个节点指回第一个节点**：

```
   普通单向链表（一条道走到黑）
   first ──► [1] ──► [2] ──► [3] ──► [4] ──► null
                                             ↑ 报数报不下去了

   环形单向链表（尾指回头，永不断路）
        ┌────────────────────────────┐
        ↓                            │
   first ──► [1] ──► [2] ──► [3] ──► [4] ──┐
              ↑                            │
              └────────────────────────────┘
   判断"走完一圈"的依据不再是 null，而是"我又回到 first 了"
```

**这是本篇最重要的一句话：环形链表里再也没有 `null`，终止条件从"遇到 null"换成"遇到 first"。** 后面每一个 `while` 都受这条规矩支配，写错就死循环。

## 二、三个角色

```java
class Boy {                       // 节点：只有一个 next，所以是"单向"环形
    private int no;               // 编号（1..nums）
    private Boy next;
    // 全套 getter/setter，节点字段是 private —— 注意这跟 HeroNode 的 public 字段不同
}

class CircleSingleLinkedList {
    private Boy first = null;     // ★ 只有一个指针 first，没有 head 哨兵！
    addBoy / showBoy / countBoy
}
```

**和单链表那篇最大的结构差异：这里没有哨兵头节点。** `first` 直接指向第一个真实小孩。这带来两个后果（第五节会看到它们的代价）：

| | 单链表（有哨兵 head） | 环形链表（无哨兵，只有 first） |
|---|---|---|
| 判空 | `head.next == null` | `first == null` |
| 删除头节点 | 和普通节点一样 | 必须特判，且 `first` 本身要改，外面还得能拿到新 first |
| 删除任意节点 | 靠"前驱指针 temp" | 靠 `helper` 指针——**必须始终停在 `first` 的前面** |

所以 `countBoy` 里那个 `helper` 不是可选的辅助变量，它是**用来替代哨兵的前驱锚点**：哨兵的作用就是"永远知道目标前面是谁"，环形链表没有哨兵，就用 `helper` 顶这个缺。

## 三、`addBoy`：建圈是分两次连的

```java
for (int i = 1; i <= nums; i++) {
    Boy boy = new Boy(i);
    if (i == 1) {
        first = boy;
        first.setNext(first);   // ★ 自己指向自己，先成一个"单人环"
        curBoy = first;
    } else {
        curBoy.setNext(boy);    // ① 上一个指向新的
        boy.setNext(first);     // ② 新的指回第一个（封口）
        curBoy = boy;           // ③ 辅助指针往后挪
    }
}
```

逐步看图（`nums = 4`）：

```
   i=1  first ──► [1] ─┐              单人环：1.next = 1
              ▲        │
              └────────┘      ← 这一步不做，后面 ② 就没有 first 可指

   i=2  first ──► [1] ──► [2] ──┐     curBoy 从 1 挪到 2
              ▲                 │
              └─────────────────┘     ← ② 每次新节点都要自己封口

   i=3  first ──► [1] ──► [2] ──► [3] ──┐
              ▲                         │
              └─────────────────────────┘

   i=4  first ──► [1] ──► [2] ──► [3] ──► [4] ──┐
              ▲                                 │
              └─────────────────────────────────┘
```

两个容易忽略的点：

1. **`first.setNext(first)` 不是可有可无的收尾**。如果 i=1 时不自我成环，`first.next` 是 `null`；那么 i=2 的 `boy.setNext(first)` 虽然让 2 指回 1，但 1 的 next 已经被 ① 改成 2 —— 恰好也成环。**但一旦中途遍历（比如只建 1 个人就 showBoy），没封口的 `null` 会让你掉进 `while(curBoy != null)` 的死路**。所以自我成环是"任何时刻链表都合法"的保证，这是环形数据结构的标准做法。
2. **封口动作发生在每一个新节点身上（②），不是最后统一连一次**。因为 `curBoy` 每次都被 `boy.setNext(first)` 更新了尾巴的指向，最后只需保持链条不断即可。反过来想：如果你只在循环结束后连一次 `curBoy.setNext(first)`，中间状态是不完整的环，遍历逻辑就得区分"建到一半"和"建完了"。

`nums < 1` 时打印"nums的值不正确"并 `return`（空圈不会被创建）✓。

## 四、`showBoy`：终止条件是"绕回来"，不是"遇到 null"

```java
Boy curBoy = first;
while (true) {
    System.out.println("编号：" + curBoy.getNo());
    if (curBoy.getNext() == first) break;   // ★ 下一个就是 first，说明我已经打印到最后一个了
    curBoy = curBoy.getNext();
}
```

顺序很关键：**先打印，再判断，最后才挪指针**。

```
   打印 1 → 看 1.next==first? 不是(=2) → 挪到 2 → 打印 2 → ...
   打印 4 → 看 4.next==first? 是！→ break

   ❌ 如果写成 while (curBoy != null)：环里永远不会是 null → 无限循环
   ❌ 如果把判断放在打印前面（先 if(next==first) break 再打印）：最后一个人会漏掉不打印
```

空圈的特判 `first == null → 打印"链表为空"` 也在前面挡住了（实测：`new CircleSingleLinkedList().showBoy()` 输出 `链表为空` ✓）。

## 五、`countBoy`：双指针报数出圈（本篇核心）

```java
// ① helper 先绕到圈尾，成为 first 的前驱
Boy helper = first;
while (helper.getNext() != first) helper = helper.getNext();

// ② 定位起始报数点：first 和 helper 同时挪 startNo-1 次
for (int i = 0; i < startNo - 1; i++) { first = first.getNext(); helper = helper.getNext(); }

// ③ 一圈圈报数：同时挪 countNum-1 次，first 落到的人出圈
while (true) {
    if (first == helper) break;                       // 圈里只剩 1 人
    for (int i = 0; i < countNum - 1; i++) { first = first.getNext(); helper = helper.getNext(); }
    System.out.println("编号：" + first.getNo() + "出圈");
    first = first.getNext();                          // first 先迈过要出局的人
    helper.setNext(first);                            // ★ helper 搭桥，把它摘掉
}
System.out.println("最后剩下编号：" + first.getNo());
```

### 为什么 helper 必须事先停在尾巴上

因为出圈那一刀是 `helper.setNext(first)` —— **改的是被删节点的前驱**，这跟单链表删除必须找前驱是同一条铁律（见 [单链表.md](./%E5%8D%95%E9%93%BE%E8%A1%A8.md) 第四节）。环形链表没有 `temp.next.next` 那种"从后面伸手"的余地，只能让前驱自己往前够。

```
   出圈瞬间（first 指着要出局的人，helper 永远停在他前面）：

   helper ──► [出局] ──► next        helper ╳ ── ─ ─ ─ ─ next
                                       └────── 一根新线跨过 ──────┘
   helper.setNext(first.getNext()) 的效果，代码里分两句写：
       first = first.getNext();      // 先把 first 抬到下一个人（顺序不能倒！）
       helper.setNext(first);        // 再让 helper 指向它
```

**这两句的顺序是硬约束**：如果先写 `helper.setNext(first)`，此时 `first` 还是那个要出局的人，等于让 helper 指向自己该删的人 —— 圈没断开，出圈失败，最后必然死循环。这跟第三节 `addByOrder`、链栈 `push` 是**同一条铁律的第 N 次登场**：改写指针前，先确认要用的旧值还没被覆盖。

### 为什么两根指针要"同步走"

`first` 和 `helper` 每次都一起挪一格，于是**它们之间的距离恒定：helper 永远是 first 的前驱**。这就是单链表"删除要找前驱"问题在环里的解法——不用每次从头再找一遍，把前驱一路带着走。代价是多一个指针变量，赚的是每次删除 O(1) 而不是 O(n)。

## 七、⚠️ 实测发现的三个真实问题（探针跑出来的）

### 问题 1：`countBoy` 内部偷偷 `addBoy(nums)` 重建圈（隐藏副作用）

```java
public void countBoy(int startNo, int countNum, int nums) {
    ...
    addBoy(nums);        // ← 一个"算出圈顺序"的方法，把链表重新建了一遍
```

探针实测（先建 5 人圈，再调 `countBoy(1,2,3)`）：

```
addBoy(5) 后 showBoy：      1 2 3 4 5
countBoy(1,2,3) 结果：      编号：2出圈 / 编号：1出圈 / 最后剩下编号：3
之后再 showBoy：            编号：3            ← 圈里只剩 1 个人了
```

三个层次的毛病：

- **方法名和行为不符**：调用者以为"我已经建好 5 人圈了，你帮我算"，实际它按参数 `nums` 重建成 3 人圈。想改人数只能改参数，`addBoy` 白调了。
- **不能只算不建**：如果哪天你手工建好一个特殊的圈（比如编号不连续）再调 `countBoy`，会被它原地替换掉。
- **好在可以重复调用**：实测连着两次 `countBoy` 都能正常出结果，因为每次都会重建。也就是说——**main 里那句 `addBoy(5)` + `showBoy()` 和后面的 `countBoy` 其实毫无关系**，纯展示。

干净的拆法（二选一）：

```java
// 方案 A：countBoy 只负责算，建圈交给调用方
public void countBoy(int startNo, int countNum) {   // 去掉 nums 参数
    if (first == null) { System.out.println("链表为空，无法计算"); return; }
    ...
}
// main: circle.addBoy(8); circle.countBoy(2, 2);

// 方案 B：留着 nums，但把"建圈"和"出圈"的边界写进注释/Javadoc，别让调用者猜
```

### 问题 2：圈里只有 1 个人时，输出自相矛盾

实测 `countBoy(1, 1, 1)`：

```
编号：1出圈
最后剩下编号：1          ← 同一个人既"出圈"又"剩下"
```

原因：`while (true)` 里的 `if (first == helper) break;` 这个只剩一人的判断被放在了**循环体开头**，而本次实测的执行路径是——`helper` 找尾巴时 `helper.getNext() == first` 直接不进入循环（自己就是尾巴），于是 `helper == first`；接着 `countNum-1 = 0` 次挪动后照样打印"1出圈"，`first = first.getNext()` 还是自己，`helper.setNext(first)`，再判 `first == helper` 才退出。**结果是先宣布出圈、再宣布剩下。**

修法：把退出检查放在报数之前之外，对 `nums == 1` 特判：

```java
if (first == helper) {                     // 圈里只剩一个人
    System.out.println("最后剩下编号：" + first.getNo());
    return;                                // 不再走"出圈"分支
}
```

### 问题 3：`nums < 1` 的校验是"顺带"生效的，职责重叠

`countBoy` 的守卫是 `startNo < 1 || startNo > nums || countNum < 1`。实测 `countBoy(1,1,0)` 能打印"参数输入有误" ✓ —— 但不是因为检查了 `nums`，而是因为 `1 > 0`（`startNo > nums`）撞上了。探针另外三组非法参数 `(0,2,5)`、`(9,2,5)`、`(1,0,5)` 也都被拦下 ✓ 行为没问题，但 `nums < 1` 这条本该显式写出来（`addBoy` 里有，`countBoy` 里靠推导），否则将来有人改 `startNo` 的默认值就会漏。

顺带一个观察：**出圈过程会真的破坏圈**（`helper.setNext` 一路摘人），所以算完之后圈只剩最后一人。语义上没错，但别指望算完还能原样 `showBoy`（实测见问题 1）。

## 八、复杂度账本

| 方法 | 时间 | 说明 |
|---|---|---|
| `addBoy(n)` | O(n) | 每个节点两句赋值 |
| `showBoy()` | O(n) | 绕一圈 |
| `countBoy(n, k)` | **O(n·k)** | 每出圈一个人平均数 k 次；最坏 O(n·k) |
| 空间 | O(n) | n 个 `Boy` 节点 |
| 找 `helper`（定位尾巴） | O(n) 一次 | 只在建圈后做一次；若想省掉就存 `last` 指针 |

数学递推公式能做到 O(n)（只求最后剩下的人，不求顺序）：

```java
// Josephus 递推：下标从 0 起算，最后结果 +1 才是本项目的编号
int last = 0;                                  // n = 1 时的解
for (int i = 2; i <= n; i++) last = (last + k) % i;
System.out.println("最后剩下编号：" + (last + 1));
```

但**链表模拟仍然是更有教学价值的写法**，因为公式只给"最后剩下谁"，而题目要的是**完整出圈顺序**——那必须真刀真枪地一遍遍摘节点。

## 十、一句话记住约瑟夫环

> **环形单向链表就是把尾节点的 next 指回 first，从此判空看 `first == null`、遍历结束看"绕回 first"而不是看 null；没有哨兵，所以出圈必须带一个 helper 指针当"活的前驱"，它和 first 同步挪动、始终保持 helper 在 first 前面一人；摘人 = `first = first.getNext()` 再 `helper.setNext(first)`，顺序绝对不能反；`countBoy` 内部又调了一次 `addBoy(nums)`，这意味着外面建的圈会被它偷偷替换、而且算完之后圈就残了。**

## 十一、往下学什么

1. **先修第七节那两个真问题**：`countBoy` 去掉内部 `addBoy`（或补 Javadoc 说明它会重建），再给 `nums == 1` 加特判。
2. **循环双向链表版**：`Boy` 加 `pre`，就能**双向报数**（奇数顺时针、偶数逆时针这类变体），出圈时同时要缝 `pre` 和 `next` 两侧 —— 正好复用 [双向链表.md](./%E5%8F%8C%E5%90%91%E9%93%BE%E8%A1%A8.md) 第四节"少连一根线"的教训。
3. **数组模拟约瑟夫环**：`int[] kids` + 下标 `(i + k - 1) % n` 的绕圈，跟 [环形队列.md](../queue/%E7%8E%AF%E5%BD%A2%E9%98%9F%E5%88%97.md) 的 `%` 是同一招；但数组"删除"要么置 0 标记、要么整体前移，对比之下更能体感链表删除的优势。
4. **对比 JDK**：`LinkedList` 的 `listIterator` + `remove()` 也是"带一个游标边走边摘"的思路。
5. **回头做栈/队列的压轴练习**：[栈.md](./%E6%A0%88.md) 里挂着的括号匹配、双栈计算器，正好可以用 [ArrayStackDemo.java](../stack/ArrayStackDemo.java) 或 [LinkedStackDemo.java](../stack/LinkedStackDemo.java) 当底层（`stack` 包里的 [Calculator.java](../stack/Calculator.java) 就是这道题，仍在开发中，详情的状态见 [数组栈.md](../stack/%E6%95%B0%E7%BB%84%E6%A0%88.md) 第十三节）。
